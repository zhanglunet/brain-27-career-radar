## 1. 借鉴对象、许可证与不复用红线

借鉴对象：sherlock-project/sherlock，**MIT（实测）**。

- **复用**：MIT 允许复用；但本设计**只借鉴「按用户名扫公开站点清单」的聚合形态**——站点清单、命中判定、聚合报告全部按求职场景自研；如实现引用原仓结构，保留原版权声明并注明出处（sherlock © sherlock-project，MIT License）。

## 3. 聚合内核设计

### 3.1 来源词表（封闭集，R1）

| source_id | 形态 | 采集内容（占位） |
|---|---|---|
| `company_site` | 公司官网公开页 | 产品/新闻/团队规模公开段 |
| `public_job_page` | 官网招聘页公开列表 | 在招职位名/要求摘要 |
| `public_event` | 公开发布会/演讲公开页 | 公开议程/演讲人信息 |
| `public_academic` | 公开学术主页 | 公开发表列表 |

- 词表四项封闭——扩展走词表增补评审（每个新来源须论证「纯公开+零凭证+可 GET」）；
- 每来源一个**注入式采集器**接口（`fetch(source_id, query) → entries`）——零内置站点硬编码，测试全 stub。

### 3.2 聚合产物 schema（T2 预埋）

```json
{
  "schema": "public-info-aggregate/v1",
  "target": {"kind": "company", "name": "公司 C-001（占位）"},
  "entries": [
    {"source_id": "public_job_page", "url": "https://jobs.example.invalid/1（占位）",
     "captured_at": "2026-11-09T09:00:00Z", "summary": "在招职位摘要（占位）"}
  ],
  "blocked": [{"source_id": "company_site", "reason": "source_blocked（反爬拒绝，如实显形）"}],
  "note": "仅公开来源聚合，背景参考——求职动作走既有批准门"
}
```

- `entries[]` 每条必带三件套（R2）；`blocked[]` 显形记录不可得来源（R3 不伪装）；
- **零推理**：聚合只并排列出来源条目，不生成「公司评价/倾向判断」——研判归人工（与既有 monitor 系列「采集归采集、研判归研判」一致）。

### 3.3 一键聚合流程（确定性）

1. 目标解析：按公司名/目标人 id 构造查询（词表内逐来源）；
2. 逐来源采集（注入式 fetch；单来源失败 → `blocked[]` 显形，不中断整体）；
3. 条目校验（三件套齐备才入 entries）；
4. 按来源+时间排序输出报告。

## 4. 失败闸门（T3 落地）

| 错误码 | 触发 | 行为 |
|---|---|---|
| `SOURCE_BLOCKED` | 目标站拒绝/反爬 | `blocked[]` 显形，不重试不伪装 |
| `SOURCE_UNREACHABLE` | 网络不可达 | 同上显形 |
| `ENTRY_INCOMPLETE` | 采集条目缺三件套任一 | 该条丢弃 + 显形（不落库） |

- 全部来源 blocked → 报告仍产出（entries=[]，blocked 全显形）——「一无所获」也是如实结果。
