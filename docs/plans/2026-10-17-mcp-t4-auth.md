## 设计

```
请求 → authenticate（400）→ checkRateLimit（429+retry_after）→ 缓存命中？
  → 是：直接返回（仍计配额）
  → 否：loadEntries？→ 成功：刷新快照 → dispatchToolCall → 写缓存
                     → 抛错：有快照 → stale: true 返回；无快照 → 503
```

- **配额**：匿名 30 req/min，token 300 req/min（可配置）。匿名超限的 429
  附带"提供有效 token 可提升配额"提示；token 无效直接 400 fail-fast。
- **Token 校验**：默认 allowlist（配置注入，未配置 = 全部拒绝）；
  生产替换为 HMAC/JWT 校验器即可，无需改本模块。
- **限流键**：token 档用 FNV-1a 哈希（非加密，仅去标识化）；
  匿名档用调用方传入的 callerKey（建议传客户端 IP），缺省共用桶。

## 取舍（已写入代码注释）

1. **缓存命中仍计配额**：fail-closed，限流同时保护 API 本身不被刷。
2. **缓存键 = tool + 参数哈希，不含身份**：结果与身份无关（只读公开
   数据），配额才分档；同一份缓存服务所有档位。
3. **stale 结果不写缓存**：源恢复后下一次调用即重试，不会长期喂旧数据。
4. **默认拒绝**：未配置 token/校验器时任何 token 都无效。
5. **时钟可注入**：`config.now`，测试确定性；生产默认 `Date.now`。

## 接线（server 层责任，本 PR 不做）

- 把客户端 IP 传给 `callerKey`；把 `stale: true` 透出给调用方。
- 从环境变量注入 `tokens` 或自定义 `verifyToken`。
- `RateLimitState` / `ResultCache` / `StaleStore` 由 server 持有、跨请求复用；
  多实例部署需换外部存储（Redis），本模块的 Map 实现是单进程版。
