# PRD-203/T1：目标站点与字段抽取规范（机会页深读）

> trend issue #1015。对应 PRD-203（中央仓库 zhanglunet/trend）。
> 地位：T1 规范稿——目标站点清单与字段抽取规范评审通过后，T2（JS 渲染页读取与结构化抽取实现，#1016）、T3（与 PRD-117 聚合搜索对接，#1017）、T4（截止日期与硬性要求显式标注，#1018）、T5（验收试运行，#1019）均以本文为准；实现不得擅自增删字段、枚举与降级码。
> 借鉴声明：vercel-labs/agent-browser 本轮未核实许可证——只借鉴「agent 浏览器读页」思路（用真实浏览器渲染页面再读 DOM），不复用其任何代码、提示词或资产。本文所有字段、枚举与流程均为自研表述。本 PR 为纯加法 .md，无代码。

聚合搜索（PRD-117）解决的是「找得到」：从聚合源拿到机会的标题、机构、链接和一段摘要。但摘要里最要紧的几件事经常缺失或含糊——薪资到底多少、截止日期是哪天（哪个时区）、联系谁、要不要在读证明。这些信息只在机会页正文里，而且越来越多站点是 JS 渲染页，普通抓取只能拿到空壳。本设计定义「机会页深读」：把机会页真正打开、渲染、读全，再按统一规范抽成结构化字段回填机会条目。本设计只定「读哪些站点、抽哪些字段、抽不到怎么办」，不写实现。

## 一、定位与边界

### 1.1 与 PRD-117 的划界

| 维度 | PRD-117（聚合搜索） | PRD-203（本文，机会页深读） |
|---|---|---|
| 回答的问题 | 找得到：哪里有机会 | 打得开、读得全：机会页里具体写了什么 |
| 输入 | 关键词、聚合源列表 | 机会页 URL（来自 117 命中、云端机会条目或人工提交） |
| 数据粒度 | 标题/机构/链接/摘要片段 | 字段级结构化抽取（薪资、截止、联系方式、硬性要求…），每字段带原文出处 |
| 页面处理 | 静态抓取即可 | 必须真实渲染（JS 执行后读 DOM） |
| 失败处理 | 源不可用则跳过 | 必须留降级记录并开放人工补录（§五），不允许静默丢弃 |
| 产出去向 | 机会条目（待深读） | 回填同一机会条目的字段与证据链 |

一句话：117 负责把机会「捞上来」，203 负责把每条机会「读透」。203 不做新的机会发现，不改 117 的源清单与搜索口径。

### 1.2 与相邻 PRD 的关系

- **PRD-176（真实性三态）**：203 只抽「页面写了什么」（事实层），不判真伪；真伪判定仍归 176。203 产出的字段证据（excerpt + 出处）正是 176 复核 deadline / contact 等维度的输入。203 抽到「邮箱域名与机构不一致」这类现象时只记录原文，不下结论。
- **PRD-175（批准门）**：203 不产生任何投递动作。深读结果只用于展示、筛选与标注；投递、发信一律走 175 批准门，本 PRD 范围内不存在例外。
- **PRD-080（本地申请助手）**：深读字段回填云端机会条目后，经既有只读通道下发本地（PRD-018/019），本地缓存继承方式与 PRD-176 §2.3 同口径——本地只读，不回写。

### 1.3 非目标（明确不做）

1. **不自动投递**：不填表、不提交、不发邮件。投递归 PRD-175 批准门。
2. **不绕过访问控制**：不破解验证码、不绕付费墙、不使用他人账号登录抓取；遇登录墙按 §五降级记录处理。
3. **不复用 agent-browser 代码**：许可证未核实，只借鉴思路（见文首借鉴声明）。
4. **不做真伪结论**：不输出「可信/可疑」判定（归 PRD-176）。
5. **不抓个人主页与社交平台**：导师个人主页、社交账号不在目标站点清单内（导师信息只从机会页正文抽）。

## 二、目标站点清单

以 RA 机会源为主，按页面形态与系统类型分组。域名均为公开机构站点的类别示例（占位性质，T2 落地时以云端 sources 表登记为准）；本文不出现任何内部主机名、IP、账号或密钥。

| 组 | 类别 | 示例域名（公开） | 页面形态 | 预期难点 |
|---|---|---|---|---|
| A | 高校官方招聘页（院系/实验室直发） | `ox.ac.uk`、`cam.ac.uk`、`ucl.ac.uk` 等高校主域下的 jobs 子站 | 混合：老页面静态 HTML，新系统 JS 渲染 | 同一学校多套系统并存；正文结构差异大；截止时间常写在正文段落而非独立字段 |

| D | 学术招聘聚合页 | `jobs.ac.uk` 类学术招聘聚合站、学科社区职位板 | 静态为主，列表页 JS 分页 | 聚合页是二手信息，关键字段必须回源站核对（与 PRD-117 命中对接时以源站为准）；过期岗位混杂 |
| E | 基金会/奖学金与博士项目页 | 基金会官网、博士培养计划（如 DTP/CDT 类）项目页 | 静态为主 | 资助信息与岗位信息分属不同页面；截止日期分轮次（多轮申请）；「在读证明」类要求常写在 eligibility 长文中 |

清单维护规则：

- 新增站点先进云端 sources 登记（域名、组别、渲染类型），再纳入深读范围；T1 不冻结具体站点全集，只冻结分组与登记字段。
- D 组（聚合页）深读结果只作线索：薪资、截止、联系方式三类关键字段必须能追溯到源站页面出处，否则按 §3.1 标 `secondhand_unverified`，不直接回填为确定值。
- 每组至少备 3 个公开样本页供 T2 开发与 T5 验收抽样（样本 URL 在 T2/T5 任务内维护，不写进本规范）。

## 三、字段抽取规范（核心）

### 3.1 通用约定（所有字段适用）

1. **每字段必带证据**：抽取结果统一形状对齐云端既有 `fieldEvidence`（fieldName / fieldValue / excerpt / extractor / confidence），203 在此之上加三项：`source_block`（页面区块标识，如 `header_meta` / `salary_block` / `body_text` / `sidebar` / `footer_contact`）、`raw_text`（字段原文片段，未加工）、`extract_status`（见下）。证据链不另起体系，T3 回填时直接写 fieldEvidence。
2. **extract_status 枚举**（字段级）：`ok`（抽到且校验通过）/ `raw_only`（只抽到原文，结构化解析失败，原文保留）/ `not_stated`（页面确实未写）/ `not_found`（预期区块存在但未定位到）/ `secondhand_unverified`（仅聚合页有、源站未核对到）。后四种都是**显式状态**，不允许用空字符串或 null 冒充。
3. **原文优先原则**：任何结构化值都必须能回指 raw_text；结构化与原文冲突时以原文为准并把状态降为 `raw_only`。尤其截止日期：**没有原文出处，不准生成日期值**。
4. **置信度**：extractor 给 0–100 自评；关键字段（截止日期、薪资、在读证明要求）confidence < 80 时，T4 展示层必须同时展示原文，不许只显示结构化结果。
5. **回填映射**：深读字段回填云端 opportunities 与本地 `MatchOpportunity` 既有字段（title / org / type / region / funding / deadline / mentors / requirements）时不新造同义字段；既有字段装不下的（如联系方式、原文出处）走 fieldEvidence 与 §3.3 的扩展结构。

### 3.2 核心字段表

| 字段 | 类型/格式 | 必填 | 主要抽取来源 | 校验规则 | 抽不到时降级 |
|---|---|---|---|---|---|
| `title` 职位名称 | string | 必填 | 页面标题区 / header_meta | 非空；与列表页标题不一致时以详情页为准并记录差异 | 整页降级（无标题不回填，进 §五记录） |
| `org` 机构 | string | 必填 | header_meta / 页眉机构名 | 与源站域名机构一致性仅记录，不判定（归 176） | `not_found`，人工补录 |
| `opportunity_type` 机会类型 | enum：`phd / ra / postdoc / fellowship / internship / other` | 必填 | 标题 + 正文自述（如 "Research Assistant"、"PhD studentship"） | 判定依据片段必须留 excerpt；标题与正文冲突时以正文为准 | `other` + 原文保留，T4 复核 |
| `salary_range` 薪资区间 | object（§3.3） | 可选 | salary_block / 正文薪资段 | min ≤ max；币种为 ISO 4217 代码；年薪/时薪/月薪口径必须显式 | 见 §3.3 分级降级 |
| `deadline` 截止日期 | object（§3.4） | 必填（可为状态值） | 正文截止段 / header_meta | 必须带原文出处；解析值与原文可互证 | 解析失败标 `parse_failed` 只留原文（§3.4） |
| `contact` 联系方式 | object：`{emails[], links[], person?, role?}` | 可选 | footer_contact / 正文「联系」段 / 申请说明区 | 邮箱过 RFC 基本格式校验；链接须为页面内真实 href | 只有站内表单时标 `form_only`；全无标 `not_stated` |
| `enrollment_requirement` 在读证明要求 | object：`{required: yes/no/not_stated, raw_statement}` | 必填（状态） | eligibility / 申请资格段 | `required=yes` 时 raw_statement（原文表述）**强制必填** | 未写明标 `not_stated`，不得默认为 no |
| `degree_requirement` 学位要求 | object：`{min_degree: bachelor/master/phd_in_hand/none_stated, field?, raw_statement}` | 必填（状态） | eligibility 段 | 要求 PhD 已到手写 `phd_in_hand`，与「PhD 在读可投」严格区分 | `none_stated` + 原文保留 |
| `mentor_lab` 导师/实验室 | object：`{mentors[], lab?, lab_url?}` | 可选 | 正文项目描述段 / sidebar | 人名只取页面明示的 PI/导师/联系人角色，不从页脚版权行猜 | `not_found`，可空回填 |
| `funding_type` 资助类型 | enum：`full_scholarship / partial / salaried / self_funded / not_stated` + `funder?` | 可选 | 正文资助段 / salary_block | 与 salary_range 互证：标 salaried 却无薪资原文时降 `raw_only` | `not_stated` |

### 3.3 薪资区间（salary_range）细则

结构：`{min, max, currency, period, raw_text, tax_note?}`

- `min` / `max`：数字（整数或两位小数），单值岗位 min=max；「from £X」类只有下限时 max 为空并在 raw_text 保留原文，不许推测上限。
- `currency`：ISO 4217（GBP / EUR / HKD / CNY / USD…）。页面只给符号（£/€/$）时按站点所在国家推断并把 confidence 上限压到 79（触发 §3.1 第 4 条原文展示）；连符号都没有则 currency 置空、状态 `raw_only`。
- `period`：enum `per_annum / per_hour / per_month / stipend_annual`。时薪与年薪**不做自动换算**（工时假设不可靠），换算展示归 T4 决策（§七）。
- 原文保留：raw_text 必须包含完整薪资表述（如 "£38,784 – £41,064 per annum (pro rata)"），含 pro rata、税前等限定词不许丢弃，可另存 tax_note。
- 抽错高风险点：正文中的基金总额、项目经费不是个人薪资——抽取来源限定 salary_block 与紧邻职位描述的薪资句，离标题/职位区块过远的金额数字不采。

### 3.4 截止日期（deadline）细则 — 全规范最严字段

结构：`{date, time?, timezone, raw_text, source_block, parse_status, deadline_status}`

- `date`：ISO 8601 日期；原文含具体时刻（如 "23:59"、"midnight"）时填 time，否则为空，**不许默认补 23:59 再当作原文事实**（展示层可提示「未注明时刻，按当地日终保守处理」，但那是展示口径不是抽取值）。
- `timezone`：取站点所在机构时区（英国 Europe/London、爱尔兰 Europe/Dublin、香港 Asia/Hong_Kong、内地 Asia/Shanghai），在字段内显式写明；原文自带时区（如 GMT/BST）以原文为准并记录。禁止无时区的裸日期入库。
- `raw_text` + 出处强制：原文片段（含日期的整句）与 source_block 必填；**没有原文出处的日期一律不采**。
- `parse_status`：`ok / parse_failed / ambiguous`。多日期并存（发布日、开始日、截止日、面试日）无法消歧时标 `ambiguous` 并把候选原文全部保留，交人工定夺，**不许猜一个**。
- `deadline_status`：对齐云端既有枚举 `confirmed / estimated / rolling / unknown / closed`：页面明示确切日期=confirmed；「招满为止」=rolling；页面已过期或明示关闭=closed；只有原文无解析值=unknown（且 parse_status=parse_failed）。
- 相对日期（"two weeks from now"、"本月底"）不换算为绝对日期：标 estimated 并保留原文与页面抓取时间戳，换算口径留 T4。

### 3.5 联系方式细则

- 邮箱：可多个（如导师与行政各一），每个邮箱附 role 推断（pi / admin / unknown，依据所在句上下文）与 excerpt。格式校验只排明显残缺（无 @、域名无点），域名与机构是否一致只记录 `domain_match: true/false`，判定归 PRD-176。
- 链接型联系（实验室页、申请门户）：存真实 href 与锚文本；「Apply」类投递链接只记录存在与否（`apply_url_present`），**不点入、不跟随到投递表单**（§1.3 非目标 1）。
- 只有站内联系表单、无邮箱无链接：标 `form_only`，视为「联系方式未公开」，不进人工补录催办队列。

## 四、硬性要求显式标注规则（供 T4 实现，本节只定规范）

### 4.1 用户画像基线（标注的比对基准）

| 基线项 | 值 |
|---|---|
| 学历状态 | 实验心理学硕士**在读** |
| 毕业时间 | 2027 年夏季毕业（学位到手在此之后） |
| 目标 | 2027 年中/下半年到岗的 RA，或同步考虑的 PhD 项目 |
| 研究方向 | 脑科学 / 认知神经科学 / BCI / 类脑 AI |

基线变更时只改本表，标注规则不变。基线是**个人求职参数**，不写进任何站点抓取配置，不随深读请求发往目标站点。

### 4.2 冲突标注码（eligibility_flags）

字段级标注，挂在机会条目上：`[{code, field, severity, excerpt}]`，excerpt 为要求原文（必填，无原文不打标）。

| 码 | 触发条件（对机会页原文） | severity | 说明 |
|---|---|---|---|
| E1 | 要求申请时已持有 PhD/DPhil（degree_requirement.min_degree = phd_in_hand） | hard | 用户 2027 年夏季才硕士毕业，明确够不着 |
| E2 | 要求在读证明且覆盖期与用户学籍冲突（如要求申请时为在读博士、或在读状态须持续到晚于 2027 夏的时点） | hard | 与 enrollment_requirement 联动；仅「要求在读」本身不触发（用户当前在读） |
| E3 | 到岗/开始日期早于 2027 年夏季毕业时点，且原文无延期弹性表述 | hard | 开始日期来自正文 start date 原文，无原文不打标 |
| E4 | 学位门槛高于在读硕士但留弹性（如「硕士或同等经验」、要求相关领域硕士已毕业） | soft | 可能够得着，提示人工判断 |
| E5 | 经验年限要求明显超出用户阶段（如 3 年以上博士后经验） | soft | 常见于 postdoc 误投场景 |
| E6 | 国籍/签证/工作权硬性限制与用户情况可能冲突的原文表述 | soft | 只标原文，不做法律判断 |

### 4.3 标注纪律

1. **只标不删**：命中 hard 的机会照常回填、照常展示，只是显式带标——绝不静默剔除，也绝不静默混入无标列表（对应 PRD T4 验收「被标出而非静默混入」）。
2. **无原文不打标**：所有 flag 必须引用机会页原文 excerpt；模型推断、摘要转述不得作为打标依据。
3. **标注可覆盖**：人工可改判 flag（留痕：改判人、时间、理由），覆盖记录格式与 PRD-176 override 同构。
4. 本 T1 只定码表与纪律；自动打标实现、展示样式归 T4。

## 五、失败与降级规范

### 5.1 失败记录格式（deepread_failures）

每次深读失败必须落一条记录，不许静默跳过：

| 字段 | 类型 | 说明 |
|---|---|---|
| `url` | string | 目标机会页 URL |
| `opportunity_id` | string，可空 | 已有关联机会时填 |
| `stage` | enum：`fetch / render / extract` | 失败发生阶段 |
| `error_code` | enum（§5.2） | 失败分类 |
| `http_status` | int，可空 | fetch 阶段有响应时填 |
| `retry_count` | int | 已重试次数 |
| `snapshot_ref` | string，可空 | 已保存的页面快照引用（渲染后 HTML/截图），供人工与复核取证 |
| `attempted_at` | string，ISO 8601 | 尝试时间 |
| `note` | string | 自由文本（如结构变动的具体表现） |

### 5.2 失败码表

| 码 | 含义 | 默认处置 |
|---|---|---|
| F1 `http_error` | 4xx/5xx | 404/410 视为机会下架，标 closed 线索交云端审核；其余按 §5.3 重试 |
| F2 `timeout` | 加载或渲染超时 | 重试后仍失败则记录，保留快照（如有） |
| F3 `anti_bot` | 验证码/机器人校验拦截 | **不破解**；记录后转人工通道 |
| F4 `login_wall` | 需登录才能查看正文 | **不登录**；记录后转人工通道 |
| F5 `structure_changed` | 页面可读但目标区块定位失效（站点改版） | 保留全文快照，字段按 not_found 降级，转 T2 适配 |
| F6 `empty_content` | 渲染后正文为空或与职位无关 | 记录并保留快照，提示源质量問題 |

### 5.3 重试与礼貌访问

- 自动重试上限 2 次，间隔递增；F3/F4 不自动重试（重试无意义且增加被封风险）。
- 单站点访问频率遵守该站 robots 与合理间隔（默认同域名两次请求间隔不低于数秒级，具体值 T2 定并可配），不并发轰炸同一站点。
- 连续失败的站点在云端 sources 的失败计数上留痕（与 PRD-176 S8「源不稳定」信号共用同一计数，不重复造指标）。

### 5.4 人工补录通道

- 补录入口：对失败或字段缺失的机会，人工可按 §三字段表逐项填写，每项强制附原文片段或来源说明，`extractor` 记为 `human`、provenance 标 `manual`。
- 人工值优先：同一字段人工值覆盖机器值展示，但机器原值与证据保留在 fieldEvidence 历史中，不删除。
- 补录不改变失败记录：失败记录是过程事实，补录完成后追加 resolution 标记（resolved_by_manual / wontfix），不删原记录。

## 六、与后续任务的衔接

### 6.1 T2（抽取实现）接口约定

- 输入：`{url, source_group, snapshot?}`（可由 T3 或手动任务触发）。
- 输出：`{opportunity_ref, fields: FieldExtraction[], failures: DeepreadFailure[]}`，其中 FieldExtraction 形状即 §3.1（fieldName / fieldValue / excerpt / extractor / confidence / source_block / raw_text / extract_status），字段名与 §3.2 表严格一致。
- extractor 必须带版本号（如 `deepread@v1`），字段规则变更升版本；历史证据按版本可追溯。
- T2 不得新增 §三之外的回填字段；确需新增先回改本规范并过评审。

### 6.2 T3（与 PRD-117 对接）对接点

- 触发：PRD-117 搜索命中产生新机会条目 → 自动排队深读；存量机会字段过期（超过云端既有刷新口径）也可触发重读。
- 回填：深读字段写入 fieldEvidence 并更新机会条目对应字段；关键字段（deadline / salary / contact）与 117 摘要值冲突时，**以深读源站原文为准**，摘要值降为历史证据保留，不直接覆盖删除。
- D 组聚合页命中：先顺聚合页中的源站链接回源深读；回不到源站时按 §二 `secondhand_unverified` 口径处理。

### 6.3 T4 衔接

- T4 消费 §四 eligibility_flags 码表与 §3.4 的 deadline 口径实现自动标注与展示；码表增删必须回改本规范。

### 6.4 T5 验收口径（字段准确率）

- **样本**：从 §二五组中抽真实机会页组成验收集（建议每组不少于 10 页，总量不少于 50 页），人工逐字段核对。
- **准确率定义**：按「字段实例」计——结构化值与原文事实一致且出处正确记对；`not_stated / not_found` 判断与页面实际一致记对；该抽到却漏抽、值错、出处错、出处缺失均记错。
- **门槛建议**（待用户拍板，§七）：关键字段（deadline、salary_range、enrollment_requirement）准确率 ≥ 95%，且 deadline 的原文出处覆盖率 = 100%（有日期值必有出处，无例外）；一般字段 ≥ 90%。
- 失败页必须 100% 有 §五降级记录——此项不达标则验收不通过，与准确率分开计。
