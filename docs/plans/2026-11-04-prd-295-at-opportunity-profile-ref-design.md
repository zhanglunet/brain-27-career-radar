## 1. 借鉴对象、许可证与不复用红线

借鉴对象：macro-inc/macro，**AGPL-3.0（2026-10-29 经 GitHub License API 实测）**。

- **复用**：仅借鉴「@引用、不复制」的**操作形态**。
- **不复用**：AGPL-3.0 传染性——**零代码复用、零依赖引入**；解析器（T2）自研，风格对齐本仓既有「批准门单点收口 + 记录 append-only + 只提示不自动投递」纪律（approval_dispatch / gap_analysis 同族）。

## 3. 引用语法

### 3.1 形态（T2 实现口径）

| 形态 | 示例（占位） | 解析目标 |
|---|---|---|
| 机会引用 | `@机会id`（如 `@opp-2026-042（占位）`） | 机会记录 id |
| 档案引用 | `@档案vX`（如 `@档案v3`） | 档案版本记录（版本显式必填，R4） |
| 组合 | 一条求职指令可同时含 `@机会id @档案vX` | 两类分别解析，同一条审计记录 |

### 3.2 禁止形态（出现即 `REF_SYNTAX_ERROR`，不尝试理解）

- `@档案`（不带 vX）——版本缺失即语法错（R4）；
- `@机会-2026-042#岗位详情`——引用不带节锚；
- `@最新机会`、`@当前档案`——相对词不是 id（R2 的反面排除）。

## 4. @名→id 解析 schema

### 4.1 产物 schema（T2 预埋）

```json
{
  "schema": "ref-resolution/v1",
  "raw": "@档案v3",
  "kind": "opportunity|profile",
  "opportunity_id": null,
  "profile_version": "v3",
  "meta_summary": {"company": "示例公司（占位）", "role": "…（占位）", "profile_digest": "sha16:…"},
  "resolution": {"status": "resolved", "candidates": 1, "strategy": "exact"}
}
```

- `meta_summary` 只有公司/角色形态与档案内容摘要指纹——档案全文不进指令与审计（与「不复制」主题一致：投递时档案内容走既有批准门执行链，本条不搬运）。

### 4.2 解析步骤（确定性）

1. 取候选集：机会登记（工作台任务与机会记录，只读）+ 档案版本链（PRD-281 版本记录）；
2. 精确匹配：机会 id 全等；档案版本号全等；
3. 候选数裁决：=1 resolved；=0 `REF_NOT_FOUND`；>1 `REF_AMBIGUOUS`。

## 5. 歧义与失败策略（T3 预埋）

| 错误码 | 触发 | 行为 |
|---|---|---|
| `REF_SYNTAX_ERROR` | §3.2 禁止形态（含档案缺版本） | 报错回显位置 |
| `REF_NOT_FOUND` | 候选 0 | 报错 + 可用机会/档案版本清单摘要 |
| `REF_AMBIGUOUS` | 候选 >1 | 停下问 |
| `PROFILE_VERSION_GONE` | 档案版本存在但已被回滚作废 | 报错显形（回滚后作废版本引用失败，不猜"就近可用版"） |

- 词表封闭；解析返回 `Resolution | Refusal` 二型。

## 6. 求职记录审计

- 每次解析追加：`{ts, raw, kind, status, candidates, resolved_ids?, error_code?}`；
- 与求职记录（工作台既有事件链）关联——"这次求职动作引用了哪条机会/哪版档案"可回查；
- 只增不删；`ts` 注入。

## 7. 批准门不变的衔接（R1 展开）

- 解析产物（机会 id + 档案版本 + 摘要）可以作为 D1–D6 投递动作 payload 的一部分进入批准门——门内校验（载荷一致防调包）照常适用；
- 本条不新增任何绕过门的路径：解析器模块不导入 approval_dispatch 的执行方法（T4 AST 断言预埋），只允许读其记录 id。
