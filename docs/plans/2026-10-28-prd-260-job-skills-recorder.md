# PRD-260/T1：skill-recorder 式求职实操转求职技能设计（录制脱敏 + 批准门不变声明）

- 日期：2026-10-28
- 来源：2026-10-27 趋势日报 brain-27-career-radar 第 2 条，用户当日拍板采纳
- trend issue：[zhanglunet/trend#1300](https://github.com/zhanglunet/trend/issues/1300)
- 中央 PRD：`trend/adopted/PRD-260-brain27-skill-recorder-job-skills.md`
- 状态：T1 设计稿，待评审；实现类任务（T2–T4）只开 PR 不合并

## 1. 目标与非目标

**目标**：录下求职者做一次真实求职操作的步骤与意图（填表导航、简历检查动作等——**个人信息与表格内容不录、本地处理**），经人 review 后提炼为**可复用清单技能**（"投某类岗位前的检查清单"类）；提炼出的技能只含流程与清单，投递动作本身**仍强制走 PRD-175 人工批准门，门一个字节不变**。

**非目标**：
- 不产出求职文档（简历/求职信生成归 PRD-150）——本条来源是录下来的**实操过程**；
- 不做任何自动投递/自动填表的启用——录制可以观察"人是怎么填的"，技能只复述清单，绝不代操作；
- 不上云：录制、脱敏、草稿、review 全部本地。

## 2. 与既有能力的划界

| 既有能力 | 关系 |
|---|---|
| PRD-175 投递前人工批准门 | **不变声明**：本条不增加任何绕过批准门的路径；技能内容含"投递前必须过 175 门"作为固定清单项（T4 断言） |
| PRD-150 求职文档生成 | 150 产出文档；260 产出流程清单技能，文档不属于本条 |
| PRD-121/183（中文叙事/角色包） | 无关；本条是录制来源的技能 |
| 既有 local-apply 域 | 本条与 local-apply 的执行路径零交集——技能是给人看的清单，不是给执行器的指令 |

## 3. 方案设计

### 3.1 求职实操录制模型（`job-capture-v1`）

字段白名单封闭：

```json
{
  "schema": "job-capture-v1",
  "captured_at": "<ISO8601>",
  "jobseeker": "<占位 ID>",
  "task_kind": "form-navigation|resume-check|listing-triage|other",
  "steps": [
    { "seq": 1, "surface_kind": "site-form|doc|listing",
      "action": "<动作名，如 填写工作年限下拉>", "intent": "<为什么这一步>",
      "field_kind": "select|text|file|checkbox|none",
      "pi_involved": false }
  ],
  "summary": "<一句话>"
}
```

- `pi_involved`（个人身份信息参与）标记：涉及姓名/电话/邮箱/地址的具体值的步骤，**只记"此步涉及 PII（类别）"，值永不入模型**——模型里没有装 PII 值的字段；
- 禁止字段（出现即录制失败）：表单字段值、简历文本、联系方式、网站凭据、截屏。

### 3.2 脱敏规则（T2 单测）

| # | 规则 | 处置 |
|---|---|---|
| J-1 | 值形如邮箱/手机号/证件号 | 阻断：该步不落盘 |
| J-2 | 疑似简历句式（长文本 + 求职关键词） | 阻断 |
| J-3 | URL 含 token/session 模式 | 阻断 |
| J-4 | 公司内部系统词汇（本地词典） | 替换 `<INTERNAL>` |

阻断式脱敏（记录前，非事后清洗）；规则表可扩充。

### 3.3 清单技能草稿（T3）

时间线 → 技能草稿（Markdown，SKILL.md 兼容结构）：

- 内容形态是**清单**："适用场景 / 步骤清单（每步：做什么+为什么+注意什么）/ 投递前置检查项"；
- **固定清单项（不可删）**：「任何投递/提交动作前，走 PRD-175 人工批准门」——生成器强制插入，review 人不可删除该行（模板标记 `required: true`）；
- 头部 `review` 块（state/reviewer/decided_at），`source: recorded` 标记与 PRD-248 同纪律；
- 草稿经人 review（本地 diff）后才可入库。

### 3.4 投递路径断言（T4，验收核心）

- 静态断言：技能草稿与最终入库产物中，"175 门"清单项存在且 `required: true`（生成器与闸门双重校验）；
- 路径断言：本条全部代码（录制器/生成器/入库门）import 图中不出现投递执行模块（结构性测试：不含 local-apply 执行面依赖）；
- 端到端断言（T5）：技能被"使用"（示例运行）时，若流程走到投递步骤，输出的是"请走 175 门"提示而非任何执行动作。

## 4. 安全红线

1. PII 永不入模型（无字段可装 + J-1/J-2 阻断双保险）；
2. 本地处理零外联；录制/脱敏/草稿/review 全链本地；
3. 批准门不变：技能强制含 175 门清单项且 required；本条代码与投递执行零依赖（结构断言）；
4. 技能只含清单与流程复述，不含代操作指令；
5. 示例公司/岗位/表单全虚构占位，无真实密钥。

## 5. T2–T5 任务拆分（按 PRD）

| 任务 | 内容 | 验收标准（PRD 原文口径） |
|---|---|---|
| T2 | 本地录制管线（个人信息清掉） | 样例时间线无 PII |
| T3 | 清单技能草稿生成 + 人 review | 草稿含 review 状态 |
| T4 | 投递路径断言：仍强制走 PRD-175 | 断言测试通过 |
| T5 | 验收试运行：虚构求职实操→技能；投递被批准门拦住直至确认 | 无 PII/密钥；批准门有效 |

## 6. T5 验收标准

1. 虚构求职实操回放产出 `job-capture-v1` 时间线；PII 样例步骤被 J-1/J-2 阻断不落盘；
2. 草稿为清单形态，含 `required: true` 的 175 门固定项 + review 块；
3. 删除 175 门的草稿被闸门拒绝（required 项不可删断言）；
4. 本条代码 import 图无投递执行依赖（结构性测试）；示例流程到投递步骤输出 175 门提示；
5. 全产物 PII/密钥扫描 0 命中；全程零网络。
