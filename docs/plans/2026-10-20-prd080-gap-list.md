# PRD-080 对照差距清单（PRD-097 / T2）

- **参照实现**：MadsLorentzen/ai-job-search（MIT），基准 commit `d621ebe63549`（2026-10-19），依据 T1 拆解报告（`teardown-report-draft.md`）
- **本仓库实现**：zhanglunet/brain-27-career-radar 的 PRD-080 本地申请助手，以当前 main 的 `lib/local-apply/` 六个文件为准（`cli.ts` / `matcher.ts` / `drafter.ts` / `interview.ts` / `ollama.ts` / `sqlite-store.ts`，2026-10-20 读）
- **设计基准**：PRD-080/T1 设计文档（CLI + Ollama + `~/.brain27` SQLite，数据主权红线）
- **结论口径**：**抄** = MIT 代码级复用（须标注来源）；**改** = 借鉴形态、自研实现；**不学** = 不适合申博场景。每项结论附一句理由，场景适配优先——brain-27 是**博士申请**，不是社招求职。

## 一句话总判断

PRD-080 的**本地化与数据主权反超参照物**（代码层硬约束比配置层权限更硬，见文末"已对齐项"），真正的差距不在"跑在本地"，而在**产物深度与链条闭环**：四段链在 brain-27 实际只有三段（评审修订整段缺席），材料"定制"停留在建议清单与模板填充，且 CLI 的草稿至今不落盘——`sqlite-store.ts` 已实现却未接线，跨进程即失。

## 汇总统计

- 清单共 **26 项**：评估 7（G1–G7）/ 材料定制 4（G8–G11）/ 评审修订 2（G12–G13）/ 面试准备 4（G14–G17）/ 数据与存储 4（G18–G21）/ 模型调用 1（G22）/ 权限与安全 1（G23）/ 叙事与上手 3（G24–G26）。
- 结论分布：**抄 1 项**（G1）/ **改 21 项**（G2–G5、G7–G9、G11–G21、G23、G24、G26）/ **不学 4 项**（G6、G10、G22、G25）。
- "抄"只有 1 项是真实结论而非保守：参照物是 Markdown 剧本 + Python 工具 + Claude Code 生态，brain-27 是 TypeScript 程序化 CLI，两边几乎没有可直接搬运的代码；参照物的价值在**形态、规则清单与纪律**，这也正是"改"占绝大多数的原因。
- **差距关闭率预估**（T5 验收要求 ≥ 80%）：若 T3 把"抄 + 改"22 项全部落地，关闭率 = 22/26 ≈ **84.6%**，达标但余量不大；"不学"4 项建议在 T5 以"决策关闭"单独列示、不计入落地关闭率，避免口径注水。
- 特别标注的设计/实现不一致（设计有、实现无）：G18（四张表只落一张）、G19（SQLite 已实现未接线）、G20（MCP 拉取未接线）、G16（面试状态机未接线）。另有一处**实现严于设计**：G22 云端 LLM（设计留了授权通道，实现直接不做）。

## 已对齐项（非差距，供 T5 回归参照）

- **数据主权执行**：`matcher.ts` 纯函数（不联网、不落盘、不打印档案）、`drafter.ts`/`interview.ts` 无网络 import、`ollama.ts` loopback 代码层断言、SQLite 文件 0600 / 目录 0700——执行强度高于参照物的配置层权限模型。
- **AI 草稿标注**：`AI_DRAFT_MARKER` 由 `withMarker()` 写入、Ollama 润色后 `ensureMarker()` 强制补回，代码层不可绕。
- **不代发**：全仓没有任何 send/submit 能力，投递永远人工，与 PRD-080 非目标一致（参照物同样不自动投递）。
- **导师维度**：`matcher.ts` 的导师匹配（0.3）是参照物五维里没有的申博专属维度，属反向优势，不要在对齐中丢掉。

## 建议落地顺序（供 T3）

按"地基 → 低成本高杠杆 → 链条闭环 → 产物深化 → 体验补全"排：

1. **G19 SQLite 接线**（含依赖声明）：成本最小，不做完，后面所有"存档/版本/状态"都是沙上建塔。
2. **G20 MCP 拉取接线**：打通上手第一步，与 G19 同属接线欠账。
3. **G5 批量分诊**：纯函数现成，一次遍历 + 排序即可交付，立刻改变可用性。
4. **G2 硬门**：matcher 内改造，影响所有后续段的输入质量。
5. **G12 + G13 评审回路**：补上缺失的第四段；Ollama 已接线，主要是 reviewer prompt 与结构化协议。
6. **G18 + G21 状态跟踪与归档**：给 G12 的评审、G14 的备面提供地基数据。
7. **G9 材料定制深化**：产物从"建议"升级到"成品"，工作量最大、价值最高，放在地基稳固后。
8. **G14 + G16 + G17 面试段补全**：读草稿、接状态机、语义复盘，一组做完。
9. **G8 事实审计 + G1 门禁（抄）**：在自由生成（润色/评审）全面启用后收紧可信度防线。
10. **G24 setup 向导、G11 草稿自检、G23 CI 守卫、G4 低分警告、G3 轨迹维度、G7 机构缓存、G15 STAR 库**：体验与完备性补全，可并行零散推进。
11. **G26 实证叙事**：等真实使用数据产生后随 T4 落地。
