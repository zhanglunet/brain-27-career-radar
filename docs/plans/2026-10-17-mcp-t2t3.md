## T1 衔接

- T2 复用 `lib/wiki/rag.ts` 的检索层（facets 过滤 + confidence 加权 + status 过滤），不另起一套排序逻辑；无 direction 时为纯列表模式（同样过滤面，按 last_verified 排序）。
- T3 截止日分组排序遵循 T1 §三：N 天内的 fixed 按 days_left 升序在前；estimated / rolling / tbd 单独分组在后；已过截止日的 fixed 标为 past 组（T4 自维护 agent 会将其翻为 expired）。
- 错误码：400 参数非法（附合法值）；无结果时按 T1 返回空数组 + total=0，不抛 404；429/503 为传输层，由 T4（trend #74）实现。

## 3 条 T1 review 意见落实

1. **Tool 2 补 confidence + last_verified**：`DeadlineItem` 每条必带 `confidence / last_verified / evidence_url`（T1 原则"每个返回带 last_verified"，Tool 1/Tool 2 统一）。
2. **direction 受控词表**：`WIKI_DIRECTIONS`（v0.1，10 个词），与 Wiki 层 `facets.keywords` 共用同一份词表；非法 direction → 400 并返回合法词表。
3. **cursor 翻页**：`next_cursor` = base64url({v, after})，after 为上一页最后一条 id；同一查询内顺序稳定，翻页无重叠无遗漏；total 始终返回。

## 关键取舍（诚实说明）

1. **McpOpportunity 扩展类型**：`org / deadline / deadline_kind / funding_note` 暂不在 WikiEntry 本体中。
   没有改已合并的 `lib/wiki/schema.ts`（避免影响 12 个已有测试），而是在 MCP 模块内定义
   `McpOpportunity = WikiEntry & {...}`。缺失时按 null / "tbd" 处理，不编造；
   D1 行 → 这些字段的真实映射由 PRD-017/T5（trend #70）实现。
2. **仓库内无 MCP server**：package.json 无 `@modelcontextprotocol/sdk`，无 mcp/ 目录。
   本 PR 只交付标准 MCP tool 定义 + 纯函数 handler，不自造 server 框架；
   接入 SDK 的 wiring 示例写在 `lib/mcp/tools.ts` 文末注释（约 15 行）。
3. **零依赖**：沿用仓库约定，只用可擦除 TS（无 enum），`node --test` 直接运行；
   游标编解码手写 base64url（不用 Buffer，Workers 兼容）。
4. **low 可信度默认排除**：两个 tool 都延续 Wiki 纪律（low 默认不进结果），upcoming_deadlines 亦然。
