## 0. 一句话边界

**259 管"源活着吗、挂了怎么办"；117 / 203 管"拿它做什么"。**

259 是公开机会源的**接入与健康层**：注册、健康判定、限流标记、主备切换、审计与
doctor。它不消费机会内容——搜索聚合归 117，内容浏览归 203。

## 1. 与 PRD-117（聚合搜索层）的边界

| | PRD-117 聚合搜索层 | PRD-259 来源健康层 |
|---|---|---|
| 管什么 | **搜索聚合**——怎么找机会：查询分发、多源结果合并/去重、排序与分析 | **来源健康与切换**——源活着吗：注册校验、健康四态、主备 failover/restore、审计、doctor |
| 关心的问题 | 拿到源之后做什么（查什么、怎么并、怎么排） | 源能不能用（healthy/degraded/failed/throttled）、挂了切哪个备源 |
| 不做什么 | 不自建连接健康管理、不自行重试切换（交给 259） | 不做查询聚合、不做结果合并/排序/分析、不解读内容 |

**越界反例**（都属于违约）：

- 117 侧自己直连来源 URL、自己重试自己的镜像列表——绕过 259 的健康状态机，审计断档；
- 259 侧对拉到的机会列表做去重、排序或打分——那是 117 的聚合语义。

## 2. 与 PRD-203（自动浏览）的边界

| | PRD-203 自动浏览 | PRD-259 来源健康层 |
|---|---|---|
| 管什么 | **浏览内容**：页面渲染、阅读、信息提取——内容层面的"看" | **可达性**：目标 URL 活着吗、是否被限流——访问层面的"能不能看" |
| 关心的问题 | 页面里有什么、怎么提取 | 请求会不会白打（failed 别去）、要不要等（throttled 退避） |
| 不做什么 | 不管健康状态机、不管主备切换 | 不渲染页面、不解读/提取内容、不做任何浏览动作 |

**越界反例**：

- 203 在收到 403/连续失败后仍硬冲同一 URL——应先查 259 可达性（throttled/failed 就退避或换源）；
- 259 替 203 决定"这个页面内容可不可信"——内容判断不在 259 语义内。

## 3. 对接约定

### 3.1 117 → 259：要 `source_handle`

- 117 向 259 请求"给我一个可用的 jobs 源"，259 返回 **`(source_handle, health_meta)`**；
- `source_handle` 形态 = `opportunity-source-v1` 注册表条目的 **`source_id`**（T2 注册表已落地）；
  `health_meta` = `state()` / `doctorJson()` 的 per_source 片段（健康态、限流用量、last_error_class）；
- 117 拿 handle 只做"声明我要用哪个源"，实际连接、主备路由、失败切换全部由 259 执行
  （`failover`/`restore` + `source_failover`/`source_restore` 审计事件）；
- **117 不自建连接、不自行维护镜像重试清单**。

### 3.2 203 → 259：查 `is_healthy`

- 浏览目标 URL 的健康性先查 259 的 `is_healthy(url)` 口径：healthy/degraded → 可浏览；
  throttled → 按限流声明退避等待；failed → 别去（换源或稍后再看）；
- 浏览动作本身仍走 203 自身机制，259 只回答可达性、不碰内容；
- **实现状态诚实标注**：独立包装函数 `is_healthy(url)` 是本节约定的查询面口径，
  当前由 `OpportunityLayer.state()` / `doctorJson()` 承接（按 url→source_id 对应条目查询）；
  独立包装属后续演进项，不在本 PRD 强制。

### 3.3 事件对接

- 259 `exportEvents()` 返回 JSON 可序列化审计流（`source_failover`/`source_restore`，
  字段 source_id/from/to/reason/at），供 117/203 侧消费留痕——下游永远能回答
  "当时这条机会是从哪个源、经没经过切换拿到的"。

### 3.4 数据归属小结

| 数据/动作 | 归属 |
|---|---|
| source_handle（= source_id） | 259 发放，117 持有使用 |
| 健康四态 / 主备切换 / 审计事件 | 259 |
| 查询分发 / 结果合并排序 | 117 |
| 页面渲染 / 内容提取 | 203 |
| 机会条目（名称/公司/链接 + source_id + fetched_at） | 117 聚合产出，带 259 的溯源字段 |

## 5. 红线重申（边界文档同样受约束）

1. 只接公开来源：`auth=none` + `data_class=public` 是加载器校验项；**不绕登录墙**；
2. ToS 与限流声明必填；429 退避不硬冲、不轮换身份；
3. 切换与恢复全留审计；本文档与示例零密钥、零内网主机名/IP，一律占位（example.com 系）；
4. 259 不沾投递（PRD-175 领域）、不沾搜索聚合（117）、不沾内容浏览（203）。
