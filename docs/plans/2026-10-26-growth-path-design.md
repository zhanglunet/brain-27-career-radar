# PRD-231/T1：成长路径设计（缺口模型 / 技能标准分级 / 路径生成规则）

> trend issue #1155。对应 PRD-231（中央仓库 zhanglunet/trend）：DeepTutor 式终身个性化成长路径。
> 地位：T1 设计稿——缺口模型、技能标准分级、路径生成规则评审通过后，T2（缺口分析实现，#1156）、T3（学习路径生成，#1157）、T4（进度跟踪与路径调整，#1158）、T5（验收试运行，#1159）均以本文为准；实现不得擅自增删缺口类别、分级判据与投递触发条件。
> 借鉴声明：HKUDS/DeepTutor 许可证未核实，**只借鉴「缺口 → 路径」的产品形态，不复用其任何代码**（详见 §二）。本文所有结构、规则、判据均为自研设计。本 PR 为纯加法 .md，无代码。

PRD-080 申请助手解决的是「机会来了，怎么评、怎么备料、怎么面」；PRD-150 解决「材料怎么生成成品文档」。本 PRD 补的是两者之前的一段：**人离目标机会还差什么、按什么顺序练、练到什么可检验的标准，才值得投**。路径从机会要求反推，达标标准先行，进度可跟踪，达标后只触发投递建议、不自动投递。

## 一、定位与边界

### 1.1 做什么：成长闭环

一句话：输入是「目标机会的要求 + 用户当前画像」，输出是「带达标标准的有序成长路径」，并跟踪进度、在达标时给出投递建议。闭环四步：

1. **看缺口**：机会要求 vs 画像，逐条比对出结构化缺口（§三）；
2. **定标准**：每个缺口对应一个技能分级标准，达标判据必须可检验（§四）；
3. **排路径**：缺口按截止日、依赖关系、性价比排成有序步骤（§五）；
4. **跟进度**：证据登记驱动达标判定，进度变化触发重排与投递建议（§六）。

### 1.2 与 PRD-150 的划界：成长 vs 产出物

| | PRD-150（求职文档生成） | PRD-231（本设计，成长路径） |
|---|---|---|
| 回答的问题 | 材料怎么做出来 | 人怎么长成能投的样子 |
| 核心产物 | .docx 简历 / 求职信成品 | 缺口清单、成长路径、达标证据 |
| 时间尺度 | 投递前数天 | 投递前数周到数月 |
| 关系 | 路径达标证据（作品、实验记录）可作为文档字段模型的素材来源 | 不生成文档、不碰模板；需要文档时交回 PRD-150 |

划界红线：路径步骤里只写「练什么、达标标准是什么」，**不生产课程内容、不内置教材、不替代 PRD-150 的文档生成**（PRD 非目标）。步骤可以建议资源类型（如「官方教程 + 一个可复现练习项目」），不做内容托管。

### 1.3 非目标（本设计明确不做）

- 不做课程内容生产与学习内容托管；
- 不做自动投递：达标只产生**建议**，投递执行走 PRD-175 批准门（§6.3）；
- 不替代 PRD-080 matcher 的匹配评分：matcher 回答「这个机会和我多合」，本设计回答「不合的地方能不能练、怎么练」；两者共用画像，不互相改写语义；
- 不把不可练的条件问题伪装成成长任务：学历门槛、地区、资助、已过截止日这类问题单列处置（§3.2 的 hard_gate 类），不进路径。

## 三、缺口模型（核心一）

### 3.1 现状锚点：matcher 已经产出什么

PRD-080/T2 的 `lib/local-apply/matcher.ts` 已在生产：三维度加权（研究方向 0.5 / 导师匹配 0.3 / 申请条件 0.2，用户 2026-10-19 拍板）打分，并产出 `gaps: string[]`——带中文前缀的自然语言缺口，如「方向缺口：……」「导师缺口：……」「学历门槛：……」「资助不满足：……」。

这套 gaps 服务的是**材料定制**（CLI 按前缀把缺口分发给 T3 草稿 / T4 面试），但直接拿来做成长路径有三处不够：

1. **无出处**：字符串里没有机会原文定位，无法满足 T2 验收「每项可溯源到机会原文」；
2. **无严重度与等级**：只有一句话，没有「差几级、差多远」，排不出路径顺序；
3. **混有不可练项**：类型 / 地区 / 资助 / 截止日 / 学历门槛是机会选择与硬条件问题，练不出来，混进路径会产生假任务。

### 3.2 缺口项结构（GapItem）

结论先行：**扩展，不复用字符串**。T2 在 matcher 之上新增结构化 GapItem；matcher 的字符串 gaps 原样保留、语义不动（现有 CLI / T3 / T4 继续用），GapItem 是并行的结构化产物（衔接映射见 §3.5）。

```ts
type SkillLevel = 0 | 1 | 2 | 3;              // 见 §四
type GapCategory = "skill" | "experience" | "credential" | "hard_gate";

type GapItem = {
  /** 稳定 ID：由机会 ID + 类别 + 规范名生成，跨重跑可对齐、可去重。 */
  id: string;
  opportunityId: string;
  category: GapCategory;
  /** 规范名，如 "EEG 信号处理"、"预注册行为实验"、"雅思总分 7.0"。 */
  subject: string;
  /** 机会要求达到的等级；hard_gate 类为 null。 */
  requiredLevel: SkillLevel | null;
  /** 画像当前等级；画像无对应证据时为 0。 */
  currentLevel: SkillLevel;
  /** 严重度 0–1，计算规则见 §3.4；hard_gate 恒为 1。 */
  severity: number;
  /** 出处（强制，见 §3.3）。 */
  source: {
    /** 机会原文逐字摘录，不得改写。 */
    quote: string;
    /** 来源字段：requirements 条目 / body 段落 / PRD-203 抽取字段名。 */
    field: string;
  };
  /** 当前等级的画像侧证据（链接 / 说明）；为空表示无证据、按 L0 处理。 */
  profileEvidence: string[];
  status: "open" | "in_progress" | "closed" | "waived";
};
```

四类缺口的处置：

| 类别 | 例 | 进路径？ | 说明 |
|---|---|---|---|
| skill 技能类 | 机会要求 EEG 处理，画像无此技能证据 | 是 | 主体，按 §四定级 |
| experience 经验类 | 要求有独立负责实验的经历 | 是 | 以「完成一次完整交付」类证据达标 |
| credential 凭证类 | 雅思 7.0、可考取的证书 | 是 | 标准天然可检验（分数 / 证书编号） |
| hard_gate 硬门类 | 要求已获博士学位、岗位已截止、地区不符 | **否** | 单列清单提示：换机会、等条件变化或用户确认 waived；不生成练习步骤 |

画像侧对应扩展：`LocalProfile.skills` 现在是字符串数组，无法表达等级与证据。T2 在本地档案侧新增技能条目视图（不改 matcher 的 LocalProfile 类型本身，由成长模块自己的档案视图读取）：

```ts
type ProfileSkillEntry = {
  subject: string;              // 与 GapItem.subject 同一规范名表
  level: SkillLevel;
  evidence: string[];           // 支撑该等级的证据（链接 / 路径 / 说明）
  updatedAt: string;            // ISO 日期
};
```

用户当前画像的基线（仅示意结构，等级以证据登记为准，不凭印象定级）：实验设计与行为测量（实验心理学本行）、统计建模、Python 数据处理、LLM/agent 工程均有实作经历可登记证据；EEG / fMRI 等神经影像管线、预注册与开放科学流程是否达标，须按 §四判据逐项核对证据后再定级。

### 3.3 来源出处强制

- 每条 GapItem 的 `source.quote` **必须非空且逐字摘自机会原文**（要求条目、详情正文或 PRD-203 抽取到的要求字段）；给不出出处的缺口**不生成**——宁可漏报，不可造缺口。
- T2 验收口径对应 PRD：缺口清单可生成且每项可溯源到机会原文。实现时测试须断言 quote 能在机会原文中逐字命中。
- 机会原文来自云端情报（公开信息）；画像、等级、证据与修正记录只存本地（沿 PRD-080 数据主权，存储口径见 §八第 6 项）。

### 3.4 严重度（severity）

severity 只表达「差多远、要求多硬」；时间紧迫度不进 severity，由 §五排序单独处理，避免双重计算：

```
等级差 levelGap = requiredLevel - currentLevel（0–3）
基础值 base = levelGap / 3
硬性系数：机会原文为必需语气（essential / required / 必须）→ 1.0
         优先语气（desirable / preferred / 优先考虑）→ 0.6
severity = round3(base × 硬性系数)；levelGap = 0 时不生成缺口
```

方向 / 导师维度的契合缺口不按技能等级计 severity：它们不是「练一个技能」能补的。T2 只有在能将其转成 experience 类条目（如「补一段与该方向相关的研究经历」，且机会原文有对应要求出处）时才生成 GapItem；转不了的只留在 matcher 总结里提示，不进路径。

### 3.5 与 matcher gaps 的衔接（映射表，T2 照此实现）

| matcher 字符串 gaps 前缀 | 处置 |
|---|---|
| 「方向缺口：」 | 线索：尝试映射为 experience 类 GapItem（须能在机会原文找到要求出处）；映射不了则不生成（保留在 matcher 总结层） |
| 「导师缺口：」 | 不生成 GapItem：导师契合靠材料与套磁解决（PRD-080 T3 范畴），不是成长任务 |
| 「类型不匹配：」「地区不匹配：」「资助不满足：」 | 转 hard_gate GapItem（severity 1，不进路径，清单单列提示） |
| 「已过截止日：」 | 转 hard_gate 并标记机会已失效：该机会的全部缺口不再进路径 |
| 「学历门槛：」 | 转 hard_gate GapItem（在读状态变化后可自动重评，如硕士毕业后） |

同时明确：GapItem 的主要来源**不是** matcher 的字符串，而是机会的要求条目（`MatchOpportunity.requirements`、`body` 与 PRD-203 抽取的要求字段）与画像技能条目的结构化比对。matcher gaps 只作交叉校验——比对产出的缺口若与 matcher 结论冲突（如 matcher 判学历不达标但结构化比对认为达标），以**机会原文**为准，并在清单中标注分歧供人工裁决。

注：PRD-203（机会页字段抽取规范，trend #1015）是并行设计，本文只在概念层引用其「要求条目结构化」产物作为 T2 输入来源之一；字段名与结构以 PRD-203 定稿为准，T2 实现时做一层字段映射，不在本设计内写死。

## 四、技能标准分级（核心二）

### 4.1 分级体系：L0–L3

| 等级 | 含义 | 一句话判据 |
|---|---|---|
| L0 无 | 未接触或无证据 | 拿不出任何可核验证据 |
| L1 入门 | 学过、能跟做 | 有学习证据，能在指导 / 教程下复现标准流程并留记录 |
| L2 熟练 | 能独立完成标准任务 | 有独立交付物：真实任务从头到尾跑通并留全程记录 |
| L3 可独立交付 | 能处理非标准问题、可被外部验证 | 有公开或外部背书产出：发表、被采用的工具、带人 / 答疑记录 |

### 4.2 可检验性纪律（本节是 T1 验收核心）

- 每级判据必须落到**第三方能打开看的证据形态**：文件、公开链接、证书 / 成绩编号、可运行的仓库与结果报告，四类之一。
- **禁止**用「熟练掌握」「深入理解」「熟悉」单独作判据；判据句子里出现程度词，必须同句给出证据形态（如「能独立完成 X（证据：仓库链接 + 结果报告）」）。
- 同一技能的四级判据构成一个 SkillStandard 条目（结构见下），标准表是数据不是代码：新增技能只加条目，不改程序。

```ts
type SkillStandard = {
  subject: string;                       // 规范名，与 GapItem.subject 对齐
  levels: Record<SkillLevel, {
    criterion: string;                  // 达标判据（须含证据形态）
    evidenceKinds: string[];            // 如 ["repo", "report", "certificate", "publication"]
  }>;
  /** 标准来源逐条注明：机会原文摘录 / 公开招聘要求 / 人工维护。 */
  source: string;
};
```

### 4.3 分级示例（两个完整条目，其余技能同构添加）

**示例 A：EEG 信号处理**

| 等级 | 判据（可检验） | 证据形态 |
|---|---|---|
| L0 | 无任何 EEG 数据处理记录 | —— |
| L1 | 跟教程完成一次公开数据集的预处理全流程（滤波 / 分段 / 伪迹剔除），记录可打开复跑 | 分析 notebook / 脚本仓库 + 运行输出 |
| L2 | 独立处理一份真实实验 EEG 数据：预处理 + 时域 / 频域分析 + 结果报告，参数选择有书面理由 | 代码仓库 + 结果报告 |
| L3 | 处理过非标准问题（数据缺失、被试脱落、设备噪声）并留处置记录；或产出被他人复用的管线 / 公开教程 | 公开仓库（有他人使用痕迹）/ 预印本或发表的方法部分 |

**示例 B：统计建模（行为数据）**

| 等级 | 判据（可检验） | 证据形态 |
|---|---|---|
| L0 | 无建模证据 | —— |
| L1 | 跟课程完成一次混合效应模型拟合与汇报，代码可复跑 | 课程作业仓库 / 报告 |
| L2 | 独立为一份真实行为数据选型、拟合、做模型诊断并写出可审阅的分析报告 | 分析仓库 + 报告 |
| L3 | 分析经受外部检验：发表 / 预印本的统计部分、或分析代码被同行复用、或为他人数据提供过建模咨询并留记录 | 发表链接 / 仓库引用记录 |

凭证类不套用技能等级表：credential 缺口的要求直接以凭证本身表达（如「雅思总分 ≥ 7.0 且单项 ≥ 6.5」写入 subject 与判据），达标证据为成绩单 / 证书编号，天然可检验。

### 4.4 标准来源与人工修正入口（PRD 风险项对策）

PRD 已知风险：技能标准分级主观。对策三条：

1. **标准引用出处**：SkillStandard.source 逐条注明来源——优先机会原文（目标岗位自己写的 essential / desirable 条目），其次同领域公开招聘要求，最后才是人工经验值（须标注「人工维护」）；
2. **人工修正入口**：用户可对两类结论做带理由的修正并留痕——(a) 修正自己某技能的当前等级（附证据或说明）；(b) 修正某机会的 requiredLevel。修正记录（原值、新值、理由、时间）随本地档案保存，T4 重排时以修正值为准，系统不得静默覆盖修正值；
3. **分歧显性化**：自动判定与人工修正冲突时不互相吞掉，清单中并列展示，供 T5 验收复盘。

## 五、路径生成规则（核心三）

### 5.1 输入与输出

输入：目标机会集合（用户钉住的目标，见 §八第 4 项）的全部 open GapItem + SkillStandard 标准表 + 画像 + 当前日期。
输出：有序 PathStep 数组（结构见 §5.3）。路径是**建议序**，不是课表：用户可跳过（skipped）或调整，调整动作触发重排（§5.5）。

### 5.2 排序原则（优先级从高到低，依次生效）

1. **截止日驱动**：步骤先按其驱动机会的 deadline 升序排——先补「最近要投的机会」缺的；无 deadline 的机会排在有 deadline 的之后；已过 deadline 的机会缺口不进路径（§3.5）。
2. **依赖关系**：同一技能内 L1→L2→L3 严格顺序（低级未达标不排高级步骤）；跨技能依赖由标准表旁的依赖声明给出（如「fMRI 预处理」依赖「Python 数据管线 L2」），按拓扑序排。成环时报错给人工，不静默乱序。
3. **性价比**：同一截止日窗口、依赖都满足的步骤之间，按 severity ÷ effortBand 权重排序——又重要又快的先练。effortBand 为粗粒度估时（§5.3），只用于排序，不作承诺。

### 5.3 步骤结构（PathStep）

```ts
type PathStep = {
  id: string;
  /** 本步同时推进的缺口（多机会共同缺口合并后可多条，见 §5.4）。 */
  gapIds: string[];
  subject: string;
  fromLevel: SkillLevel;
  toLevel: SkillLevel;
  /** 练什么：一句话动作（如「用公开数据集复现 EEG 预处理全流程并留记录」）。只给动作与资源类型，不生产课程内容（§1.2）。 */
  action: string;
  /** 达标标准：逐字引用 §四标准表中该技能该等级的 criterion，不另行改写。 */
  criterion: string;
  /** 预计投入（粗粒度，仅排序与预期管理用）：S <5h / M 5–20h / L 20–60h / XL >60h。 */
  effortBand: "S" | "M" | "L" | "XL";
  /** 排序依据快照：由哪个机会的截止日驱动。 */
  drivenBy: { opportunityId: string; deadline: string | null };
  status: "todo" | "doing" | "done" | "skipped";
};
```

### 5.4 多机会共同缺口合并

- 同 subject、同 toLevel 的缺口（来自不同机会）**合并为一步**：gapIds 收集全部来源，drivenBy 取其中最早 deadline，severity 取各来源最大值参与排序。
- 同 subject、不同 toLevel 的，按最高 toLevel 生成进阶链（L1 步、L2 步……），低阶步骤同时服务低要求机会——一步达标可连带关闭多个机会的同名缺口（§6.2）。
- 合并只在同类别内进行：skill 与 credential 不合并（练技能与考语言是两种动作）。

### 5.5 路径重排触发条件

任一发生即重排（只动 todo 步骤，doing 步骤不打断，done / skipped 不回滚）：

1. 任一步骤被登记达标或跳过；
2. 画像变化：新证据登记、人工修正等级 / 要求等级（§4.4）；
3. 目标机会集合变化：新机会钉入、机会 deadline 变更或过期、机会被取消收藏；
4. 标准表变化：新增 / 修订 SkillStandard 条目；
5. 兜底：每周定时重排一次（防遗漏的被动变化，如云端情报更新了要求条目）。

重排须产出**变更说明**（哪些步骤新增 / 删除 / 换序及原因），不静默换序——用户要能看出路径为什么变了。

## 六、进度跟踪与投递触发

### 6.1 进度状态表达

- 步骤级：PathStep.status（todo / doing / done / skipped）；
- 缺口级：GapItem.status（open / in_progress / closed / waived）；步骤进行中对应缺口为 in_progress；
- 机会级：就绪度 readiness = 1 −（该机会 open / in_progress 缺口的 severity 之和 ÷ 该机会全部缺口 severity 之和），取值 0–1，展示时保留两位小数并附缺口明细，不单独拿一个数字下结论。

### 6.2 达标判定与证据登记

- 达标只能由**证据登记**触发：用户为某步骤提交证据（链接 / 本地文件路径 / 说明），系统按 criterion 核对证据形态是否齐备——只做形态核对，不做内容真伪判断（真伪由用户与评审负责，系统不假装能验真，见 §九）；
- 证据登记后：步骤置 done、对应 GapItem.currentLevel 更新为 toLevel、满足条件时 GapItem 置 closed，并触发重排（§5.5 第 1 项）；
- 一步合并多缺口时，达标连带更新全部 gapIds 对应缺口（§5.4）。

### 6.3 投递建议触发（只建议，不自动投递）

触发条件（默认口径，可调项见 §八第 5 项）：某机会的 skill / experience / credential 类缺口全部 closed（或经用户确认 waived），且无未处置 hard_gate → 生成一条**投递建议**。建议是一条记录 / 通知，内容含：机会、就绪度、仍存的提示项（如导师契合缺口——它不挡投递，但值得知道）。

衔接红线：

- 本模块**不新增任何投递 / 发送能力**：不写 send / submit 代码路径，不调用外部投递通道；
- 用户接受建议后，后续动作完全回到既有链路：材料生成走 PRD-150 / PRD-080 drafter，任何对外执行动作走 **PRD-175 批准门**（先进批准队列、人确认才执行、全程留痕）；
- 用户忽略或驳回建议同样留痕；驳回后除非该机会缺口状态再变化，不重复建议，避免反复打扰。

## 七、与后续任务衔接（T2–T5 输入输出约定）

### 7.1 T2 缺口分析（#1156）

- 输入：目标机会（MatchOpportunity，含 requirements / body / keywords / mentors；要求字段来源含 PRD-203 抽取产物，实现时做字段映射）、本地画像（含 §3.2 ProfileSkillEntry 视图）、SkillStandard 标准表；
- 输出：GapItem[]。**验收硬口径：每项 source.quote 非空且能在机会原文逐字命中**；hard_gate 单列；与 matcher 结论的分歧要标注（§3.5）；
- 不动 matcher.ts 的 gaps 语义与权重（0.5 / 0.3 / 0.2 为用户已拍板，T2 不得改）。

### 7.2 T3 路径生成（#1157）

- 输入：GapItem[] + 标准表 + 各机会 deadline + 当前日期；
- 输出：PathStep[] 有序数组。**验收硬口径：每步 criterion 必须能在标准表中逐字回查到**（生成时不许改写判据）；排序须可复现（同输入同输出，排序键全部显式）。

### 7.3 T4 进度跟踪与路径调整（#1158）

- 输入：证据登记事件（stepId + 证据）、人工修正事件（§4.4）、机会集合变化事件；
- 输出：更新后的 GapItem / PathStep 状态、重排变更说明、满足 §6.3 条件时的投递建议事件；
- 红线：T4 只产出建议事件，不接任何投递通道；与 PRD-175 的对接点仅是「建议被接受后由既有链路接管」。

### 7.4 T5 验收口径（#1159）

以真实目标岗位回放（建议样本：一个牛津 / 剑桥 RA + 一个 PhD 岗位，均为公开情报、占位符化后入验收材料）：

1. 人工先独立规划（不看系统输出）：写下该岗位的缺口、练习顺序、达标标准；
2. 再跑系统全链路（T2 → T3），逐项对照：缺口集合、步骤顺序、标准可检验性；
3. **「大体一致」判定**：人工规划中标为必做的核心步骤全部出现在系统路径中、顺序无逆序、每步标准可检验——三者满足即通过；其余分歧（多 / 少步骤、粒度、severity 口径）逐条记录原因（标准表缺项 / 合并粒度 / 人工判断差异），有书面说明即不算失败；
4. 分歧记录回流：属于标准表缺项的，补 SkillStandard 条目；属于规则问题的，记录待 T 系列收尾时统一修订。

## 八、待决策事项清单（需用户拍板）

1. **分级粒度**：L0–L3 四级（本设计默认推荐，足以区分「不能投 / 能投 / 有竞争力」，标准维护成本低）vs L0–L4 五级（更细，但每一级都要可检验判据，标准表膨胀）？
2. **标准表冷启动**：人工先写首批条目（默认推荐：从最常投的 EEG / 行为实验 / 统计 / LLM 工程四类起步，引用真实机会原文逐条沉淀）vs 由本地 LLM 从机会原文起草、人工逐条确认后入库（快，但确认负担不小，且须防 LLM 编造判据）？
3. **证据登记方式**：手动登记链接 / 说明（默认推荐，v1 简单可靠）vs 扫描本地指定目录自动发现证据（省事，但涉及本地文件扫描授权与误报，v1 不做）？
4. **路径服务范围**：只服务用户手动钉住的目标机会（默认推荐，聚焦、噪音低）vs 对全部收藏机会自动生成缺口与路径（覆盖广，但路径会被低优先机会淹没）？
5. **投递建议阈值**：缺口全 closed 才建议（默认推荐，严格）vs 就绪度 ≥ 0.8 即建议（更早提醒，但可能在关键缺口未补时打扰）？
6. **成长数据存储**：本地 `~/.brain27/` SQLite（默认推荐，沿 PRD-080 数据主权与 sqlite-store 先例；画像等级、证据、修正记录均属个人数据，不上云）vs 云端 D1（多端可见，但与 PRD-080 红线冲突，不推荐）？

## 九、诚实说明与风险

- **分级主观性消不掉，只能管住**：§4.4 的出处引用 + 人工修正能压低随意性，但冷门技能的 L2 / L3 边界仍会争议；T5 的人工对照就是为暴露这类分歧而设，不要指望 v1 一次定准。
- **matcher 的已知局限会传导**：matcher 用子串匹配判命中（假阳性已知），其学历判断是关键词启发式；T2 若直接信 matcher 结论会产生假缺口——本设计已要求以机会原文为准、matcher 只作线索（§3.5），但原文抽取质量（PRD-203）仍是上限。
- **预计投入只是粗粒度排序信号**：effortBand 按一般学习者估，个体差异大；不得把它当承诺工期展示给第三方。
- **证据形态核对 ≠ 证据验真**：系统只核对「有没有符合形态的证据」，不判断证据内容真伪；把关在用户与评审。
- **DeepTutor 协议未核实**：本文只借形态（§二）；若日后核实结果与预期不同，不影响本文自研结构的有效性。
