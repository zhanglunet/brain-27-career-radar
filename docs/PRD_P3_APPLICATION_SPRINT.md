## 1. 背景与时间窗

今天是 2026-08-06。目标用户 2027 年毕业，2027 秋季入学的博士申请季即将开始：主要项目 2026 年 9—10 月开放申请，2026 年 11 月—2027 年 1 月密集截止（牛津/剑桥 gathered field 约 12 月上旬、HKPFS 12-01、UCL 各批次 11 月—1 月、IRC GOI 约 10 月）。从现在到最后一批核心截止日，只有约 12 周。

与此同时，体检报告确认了三件事：生产抓取自 08-02 起大面积故障且无人告警；全库 confirmed 截止日仅 6 条且未挂证据；产品没有提醒、没有申请跟踪，情报无法转化为申请动作。

因此 P3 不再按原占位方向（模型辅助 + 审核后台）展开，而是定位为一次**申请季行动闭环冲刺（Application Sprint）**：用 12 周把系统从"可审计的情报站"变成"申请季可以依赖的行动工具"。模型辅助建议顺延到申请季后（2027-03 之后）再立项。

## 2. 产品目标与成功指标

**目标**：在 2026-10-01 前，用户可以在一个页面看到全部核心目标项目的已核验截止日与材料要求，把它们订阅进手机日历并收到截止提醒，逐项记录自己的申请进度；维护者可以在 30 分钟内完成一轮候选审核，并在管线故障发生当天收到告警。

成功指标（2026-10-01 检查点）：

1. confirmed 截止日 ≥ 30 条，覆盖四大目标地区全部核心项目，且每条挂有 field_evidence 证据或官方页面复核记录；0 条无证据 confirmed。
2. 来源巡检失败数从 62 回落到 ≤ 10（不可自动访问者显式转为人工核对，不计入失败）；日报恢复非零产出。
3. 管线故障或 Cron 缺勤当天有邮件告警；生产 D1 每日自动备份且完成过一次真实恢复演练。
4. 日历可导出 ICS；confirmed 截止的 T-30/14/7/3/0 提醒邮件可送达。
5. 候选积压（机构/机会/政策）经 CLI 审核清零一轮：每条要么晋升、要么驳回留痕，不再停留在无人处理状态。
6. `npm run verify` 在 GitHub Actions 上对每个 PR 自动执行。

### 非目标（冻结至 2027-03，届时重新评估）

- 不做 SEO / SSR 数据预取 / Bot 放行优化（单用户产品，公开索引不是当前价值）。
- 不做多用户账号体系与跨设备同步；申请跟踪先用 localStorage。
- 不扩展全球地图、知识图谱、双语翻译（保底不崩即可；暂停新论文翻译以省配额）。
- 不接入 OpenAlex/Semantic Scholar/ORCID/Unpaywall/CORE 等悬置论文库。
- 不建设 Web 审核工作台（P2.6 降级为 CLI 脚本交付，Web 化留给 P4）。
- 不引入生成式模型的匹配度建议（P3.5 用可解释规则匹配作为低风险前置）。

## 3. 用户故事

1. 作为申请者，我希望看到牛津、剑桥、UCL、港三校、TCD/UCD 等核心项目 2027 入学的官方截止日、雅思要求、推荐信数量和申请入口，并确信这些信息核对过官方页面。
2. 作为申请者，我希望把所有关注的截止日一次性订阅进手机日历，并在截止前 30/14/7/3 天收到邮件提醒。
3. 作为申请者，我希望对每个机会记录"关注/套磁中/材料准备/已提交/面试/offer/拒绝"状态和备注，日历只对我关注的机会生成准备任务。
4. 作为申请者，我希望知道 HKPFS、CSC 攻博/联培、IRC GOI 等奖学金与项目申请的先后依赖关系（如 HKPFS 需在 12-01 前完成院校申请）。
5. 作为维护者，我希望管线故障当天收到告警，而不是六天后偶然发现。
6. 作为维护者，我希望用一条命令逐条审批候选（y/n），批准的自动事务写回正式表并留下审计记录。

## 4. 功能范围

### P3.0 生产止血与可观测（第 1 周，最高优先）

- FR-1 故障取证与修复：在 `checkSource` 的 catch 中把具体错误分类落库（DNS/超时/TLS/子请求超限/被封），替代当前 lastStatusCode=null 的零信息；用 `wrangler tail` 实测主 Cron 单次调用子请求总数（fetch 与 D1 语句同计），验证"08-02 来源翻倍导致子请求超限"假设；按结论拆分批次（到期来源分页处理、学术同步拆独立错峰 Cron 或加游标与预算护栏）。
- FR-2 死人开关告警：两条 Cron 末尾各 ping 一次外部心跳服务（healthchecks.io 或 Cloudflare 通知策略），失败或缺勤即时邮件通知维护者。
- FR-3 备份自动化：每日 `wrangler d1 export` 上传 R2 或私有存储并记录 SHA-256；OPERATIONS 新增备份/恢复章节（含 D1 Time Travel 口径）；完成一次从备份恢复到全新 D1 的真实演练并留痕。
- FR-4 不可自动访问来源治理：对 526/404 与疑似封禁的来源（中科院三所、OpenAI、腾讯等）更换可达 URL 或显式转为人工核对（复用 ADR-007 机制），使失败率指标反映真实异常而非常态。

### P3.1 数据可信冲刺（第 1—3 周）

- FR-5 存量复核：对全部 6 条 confirmed 与 4 条 estimated 截止日逐条对照官方页面复核；无法佐证的降级为 estimated/unknown；今后 confirmed 必须挂 field_evidence（机制已存在，种子不得再绕过）。
- FR-6 核心截止日补全：人工 + 适配器结合，补齐四大地区 2027 入学核心项目 30+ 条 confirmed 截止：牛津/剑桥神经科学与实验心理学 DPhil/PhD、UCL/KCL/爱丁堡各批次、HKPFS 及港三校院系截止、TCD/UCD 心理学与神经科学、清北推免/统考节点；全部进入统一日历。
- FR-7 材料要求结构化：opportunities 新增 language_requirement、references_count、research_proposal_required、application_fee、interview_format、portal_url 字段；对 FR-6 覆盖的核心项目逐项录入并附证据；机会卡展示"申请这个项目你需要什么"。
- FR-8 奖学金专项：新增 /scholarships 页面与数据模型，首批覆盖 HKPFS、CSC 攻博与联合培养、Gates Cambridge、Clarendon、Cambridge Trust、IRC GOI，含资格、金额、与项目申请的先后依赖；精确截止进统一日历。CSC 时间线（先 offer、次年 3 月申报）必须显式呈现。
- FR-9 爱尔兰补齐：为 TCD、UCD、SFI 中心登记来源与首批机会；IRC 奖学金进日历；在此之前爱尔兰入口页明示"建设中，当前 0 条"。
- FR-10 日期治理：日历与顶会查询按"今天"过滤，过期截止移入"已结束"分组；"紧急节点"等标签按与今天的差值动态计算；修正 counts 口径差；补齐 8 个无日期顶会的官方日期或显式 TBA；修正论文未来出版日期。

### P3.2 行动闭环（第 3—5 周）

- FR-11 ICS 订阅：新增 /api/calendar.ics，把 confirmed 截止与顶会节点序列化为 iCalendar；日历页加"订阅到我的日历"入口。
- FR-12 截止提醒：Cron 末尾对 T-30/14/7/3/0 的 confirmed 截止发送摘要邮件（Cloudflare Email Routing 或第三方 SMTP；初期只发维护者邮箱，不建订阅系统）。
- FR-13 我的申请跟踪：localStorage 保存 {机会 ID → 收藏、阶段（关注/套磁中/材料准备/已提交/面试/offer/拒绝）、备注、下一步日期}；机会卡加收藏与进度入口；新增 /my 页面按截止日排序聚合；日历优先展示"我的清单"，通用准备任务只对已收藏机会生成。
- FR-14 时区修复：calendar 的"今天"改按机会各自的 deadline_timezone 逐条计算（修复东京口径导致的提前一天丢任务）；页面展示统一为"按截止日原时区显示并显式标注"，不得把伦敦/香港截止硬转为单一时区。

### P3.3 审核出口——P2.6 的 CLI 降级交付（第 2—4 周，与 P3.1 并行）

- FR-15 审核 CLI：本地脚本读取 organization_candidates / candidate_records / policy_candidates / review_queue / change_sets，逐条展示证据，人工 y/n/skip；批准走受控事务写回 sources/institutions/opportunities/research_policies，全部落 resolved_by/resolved_at/resolution_code 审计字段。
- FR-16 积压消化：先抽样 30 条评估各候选池的真实晋升率，再据此定批量策略（低价值池可批量驳回留痕）；目标是三个候选池与 review_queue 各清零一轮。
- FR-17 鉴权红线：本期不上线任何公网写 API。若后续需要，必须使用 Cloudflare Access 或 Worker secret bearer token；app/chatgpt-auth.ts 的明文头在具备边缘签名校验前仅限展示用途，并在代码注释中写明此边界。

### P3.4 工程质量与一致性（第 4—8 周，穿插进行）

- FR-18 CI：新增 GitHub Actions 对 push/PR 执行 `npm run verify`（Node ≥22.18，engines 同步收紧）；增加"全新 D1 从 0000 顺序迁移 + 核心管线真库冒烟"步骤，替代纯 SQL 字符串断言；deploy 脚本前置 verify。
- FR-19 迁移元数据修复：补齐 _journal.json 缺失的 0002/0012/0023 条目；明确迁移工作流（承认手写 SQL 流程则冻结 db:generate 并在 OPERATIONS 写明，或重建 drizzle 快照基线）；CI 校验迁移文件数与 journal 条目一致；此后种子数据与 DDL 分离，内容更新不再走迁移。
- FR-20 数据修复：paper_authors 改用 UNIQUE(paper_id, researcher_id) 或确定性顺序，消除共著覆盖；academic_events 写库加保护避免拖垮整轮；日志类表加 90/180 天保留策略；system-status 约 30 条 COUNT 合并为批量查询。
- FR-21 API 与前端一致性：抽取公共工具统一分页/缓存/错误约定；papers/researchers 补分页；LIKE 通配符转义；GlobalSearch 补 4 类实体中文标签；修复已有数据时错误被静默吞掉；hero 硬编码统计改 API 驱动；导航配置收敛为单一来源（桌面复用手机导航分组）。
- FR-22 文档一致性与合规：按体检报告清单集中修正 README/ARCHITECTURE/PRD/OPERATIONS 的口径漂移（导师数、机构数、来源数、双 Cron、ADR 重号、P2.3 编号、CHANGELOG 版本分节）；补 LICENSE、/about（数据来源、免责、导师信息移除渠道、翻译版权口径）、联系方式；抓取层接入 robots.txt 检查与同 host 最小间隔；OPERATIONS 新增"配额与成本"章节并在 Cloudflare 设用量告警。

### P3.5 导师扩容与规则匹配（第 6—10 周，次优先）

- FR-23 导师扩容：按用户方向（认知神经/BCI/脑启发 AI）从已覆盖机构院系页批量扩充到每个目标地区 15—30 位；导师页关联近 3 年代表论文（复用 paper_authors）。
- FR-24 招生信号：导师主页巡检检测 "PhD position / opening / 招生" 关键词，将 recruitment_status 生成 watch→open 候选（进审核，不自动发布）。
- FR-25 规则匹配：用户输入研究方向标签后，用机会 tags 与导师 topics/methods 做可解释规则匹配并给出命中理由，替代手工 fit 枚举；不使用生成式模型。

## 5. 业务规则（本期新增）

- confirmed 截止日必须能追溯到 field_evidence 或复核记录；种子迁移不得再直接写 confirmed。
- 候选晋升只能通过审核 CLI 的受控事务，禁止手工批量复制候选表。
- 公网不得出现无鉴权写接口；明文请求头不得作为鉴权依据。
- 提醒与 ICS 只包含 confirmed 与官方 rolling 状态；estimated 日期在提醒中必须带"预计"标注。
- 冻结清单内的功能只修崩溃级问题，不接受新特性；相关外部建议默认作废。
- 页面展示截止日一律带原时区标注；"今天"的计算跟随各记录自己的时区。

## 6. 验收标准

1. 第 2 节 6 项成功指标全部达成，以生产 API 与 GitHub Actions 记录为证。
2. 一次全新空 D1 顺序迁移 + 真库冒烟在 CI 绿灯；`npm run verify` 通过。
3. 手机 375px 与桌面端均可完成：查看核心项目截止与材料要求 → 订阅 ICS → 收藏并标记申请阶段 → 在 /my 查看倒排清单。
4. 审核 CLI 演示：批准 1 条机构候选、1 条机会候选、驳回 1 条，均可在 D1 中查到审计字段与写回结果。
5. 故障演练：手工制造一次 Cron 失败，告警邮件在当轮送达。
6. 文档抽查：体检报告 3.3 节列出的口径漂移项全部修正，CHANGELOG 出现 v0.2.0—v0.13.0 版本分节。

## 8. 风险与依赖

- F1 故障根因若不是子请求超限（如 Workers 出口 IP 被目标站封禁），FR-4 的人工核对降级是兜底路径；两种根因都不阻塞 S1—S3。
- 邮件通道依赖 Cloudflare Email Routing 或外部 SMTP 的可用性；不可用时 ICS 订阅（FR-11）仍能独立提供提醒价值。
- 核心截止日补全依赖各校 2026 年 9—10 月陆续公布 2027 入学信息；未公布前先录 estimated 并在公布后升级，不得抢跑 confirmed。
- 单人维护（bus factor = 1）：S6 陪跑期只保留告警值守与数据核对，不排新功能。

## 9. 发布与回滚

- 沿用现行流程：发布前 verify + 全新 D1 顺序迁移验证 + 生产 D1 备份（自 FR-3 起为每日自动 + 发布前手动各一份）；迁移只新增表和列，不删除既有数据。
- 审核 CLI 的每笔写回都在事务内且有审计字段，误批可按审计记录逐条回滚。
- 提醒邮件与 ICS 为纯读扩展，回滚只需下线路由，不影响数据。
