# 自动更新架构

## 数据流

`Cron → source monitor → source_check_logs + source snapshot → adapter → candidate/evidence → change set/risk route → review queue → 已发布数据`

抓取器对响应正文设置 512 KiB 上限、12 秒超时和四路并发；失败时保留最后一次可信内容。P1 复用同一次有界响应，不额外抓取页面；只对配置了 `adapter_key` 且开启 `discovery_enabled` 的 5 个试点来源执行抽取。

P1 数据分为三层：`candidate_records` 保存按规范化 URL 去重的候选，`field_evidence` 把字段值关联到来源快照和证据片段，`change_sets` 保存与已发布机会的字段差异、风险等级和处理状态。列表适配器只发现同一注册域名内的候选链接；未知外部域名不自动启用。

来源目录为每个来源保存覆盖类型、机构类型、地区、主题、优先级和说明。当前登记 57 个官方入口，其中 51 个自动访问，6 个受限入口人工核对。Cron 每 6 小时触发；查询根据 `check_interval_hours` 只选择到期来源，31 个重点来源每 6 小时检查，普通来源每 24 小时检查。重点范围扩展到牛津、剑桥、UCL、清华、北大、香港、上海与深圳的高校和企业。

页面哈希变化先写为 `automatic/observing`，不再直接占用人工待审核队列；下一轮相同哈希会由 `automatic-policy-v1` 自动结案。新机会、解析冲突、截止日期、开放状态和资助语义仍保留人工审核。博士机会使用结构化资助字段，避免把仅覆盖 Home fees 的 studentship 误报为国际生全奖。

科研助理与一般研究岗位分开建模。`masters_eligible` 只表达硕士背景是否满足公开学历门槛，`eligibility_details` 保留逐岗条件，`phd_bridge_details` 解释可积累的实验、数据、论文或推荐信价值；系统不把受聘解释为博士录取承诺。

## 关键决策

### ADR-001：D1 作为事实存储

项目已经运行在 Cloudflare Workers 并带有 Drizzle，因此使用 D1 保存关系型、可审计的数据，避免引入外部数据库连接和凭据。

### ADR-002：静态种子作为故障降级

数据库未配置、迁移未执行或 API 临时失败时，客户端保留构建时静态种子，避免职业机会页面变成空白。降级状态必须显示为“静态快照”。

### ADR-003：监控与语义发布分离

HTTP/哈希变化可以自动记录；截止日期、状态和职业建议属于高风险语义变化，先进入审核队列。这样能自动发现变化，同时避免把网站模板变化误判为招生变化。

### ADR-004：有界抓取

采集只读取有限正文，不缓冲任意大小响应。请求超时、重定向、失败次数和最终 URL均入库。单来源失败不会中断批次。

### ADR-005：规则适配器先于生成式抽取

P1 使用来源配置、JSON-LD、DOM 元信息和确定性文本规则，所有字段都保留提取器、置信度和原文片段。模型辅助只属于 P2 草案能力，不能绕过审核发布。

### ADR-006：默认关闭自动合并

`auto_merge_low_risk` 在 5 个试点均为关闭。URL-only 变化虽被标记为低风险，也只有来源显式开启策略后才能写回；截止日期、开放状态和类别等高风险字段始终进入审核。

### ADR-007：访问受限来源保留为人工目录

牛津、帝国理工、Crick、HKUST、HKU 与 AstraZeneca 的官方页仍属于有效信息源，但自动 Worker 访问返回 403 或运行时异常。它们保持 `enabled=0`，可在来源页检索，不进入每日失败率和重复告警。

### ADR-008：稳定性自动审查不等于自动发布

自动审查只回答“页面变化是否在下一轮保持稳定”。稳定结案不会接受字段差异或修改机会；语义字段必须由确定性规则和人工审核共同确认。

### ADR-009：重点来源与普通来源分频

统一 Cron 每 6 小时触发，D1 到期查询避免每轮抓取全部网站。牛津、剑桥、UCL、清华、北大及相关重点入口使用 6 小时间隔，其余使用 24 小时间隔。

### ADR-010：科研助理作为博士前独立路径

高校 Research Assistant、科研助理和研究助理使用独立机会类型，不混入博士或企业校招。页面必须同时展示学历条件与博士过渡价值，允许用户按城市和类型筛选，并明确合同工作与后续博士录取相互独立。

### ADR-011：桌面与移动端同等可用

桌面端使用多列卡片和完整筛选；手机端改为单列卡片、横向可滚动筛选和 16px 搜索输入。关键学历、截止日期和博士过渡信息不得仅依赖 hover 或被移动端隐藏。

### ADR-012：学术实体与职业机会分表

导师和论文不是岗位，不能复用 `opportunities`。P2 使用 `researchers`、`researcher_identities`、`researcher_sources`、`papers` 与 `paper_authors` 建立实体关系，同时复用 `sources`、快照和来源检查日志。

### ADR-013：论文自动发现不等于自动核验

Crossref 查询结果必须同时通过作者规范化匹配和主题阈值，并按 DOI 幂等写入。由于同名作者和元数据不完整风险，新记录默认是 `candidate` 且 `published=false`；只有身份和来源进一步确认后才能升级为 `verified`。

### ADR-014：职业与学术管线故障隔离

同一 Cron 并行触发来源巡检和学术同步，但分别写入 `sync_runs` 与 `academic_sync_runs`。Crossref 失败不会中断职业来源更新，单导师失败不会中断其他导师；学术实体级事件写入 `academic_events`。

## 部署边界

- D1 binding：`DB`
- Cron：`01:00、07:00、13:00、19:00 UTC`，每 6 小时触发一次
- 生产 database ID 不进入代码库，通过部署环境注入。
- 本地开发使用固定 preview UUID，并将状态显式持久化到项目根目录 `.wrangler/state`，保证重新构建、迁移命令与开发服务器连接同一实例；该 UUID 不能用于生产部署。
- Workers Logs 开启；应用日志使用 JSON。
- Compatibility Date 使用 `2026-07-31`；Wrangler 已升级到 4.118.0，并完成 Worker/D1 回归。
