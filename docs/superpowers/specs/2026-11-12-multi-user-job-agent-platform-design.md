# 多用户求职 / 升学智能体平台 设计文档

- 日期：2026-11-12
- 关联：issue #137（独立私有求职空间）
- 状态：草案，待管理员确认
- 标注约定：**【已定】** 为管理员在讨论中明确的决定；**【设计者判断】** 为写文档时做的默认选择，可被推翻；**【留给实施】** 为实施者可自行决定、不影响产品形态的事项。

---

## 1. 意图与背景

现有仓库是一个"单一目标 + 公开"的系统：整个雷达围绕一个人（2027 届实验心理学硕士，脑科学 / AI 方向）设计，画像、来源、筛选口径、界面文案都绑定在这个目标上。

现在有多人需要使用，每个人背景和求职目标都不同（例如有人跟踪国内校招，有人申请博士）。因此要把系统改造成：

- **公开仓库**：只放通用功能模块（来源采集、真实性核验、机会与资格模型、智能体、审批门等），不绑定任何人的目标，不含任何真实个人数据。
- **公开实例**：现有 openagent.hk 脑科学雷达继续运行，它只是"用通用模块配出来的一个公开实例"。【已定】
- **私有平台**：一个多用户的招聘 / 求职 / 升学智能体平台。管理员（仓库所有者）管理平台；用户注册、登录，各自拥有私有数据空间与目标配置。【已定】

用户只需上传简历或描述意向，其余工作由智能体完成；**一切对外动作由智能体准备、本人点确认后才发出**。【已定】

## 2. 目标、非目标、反目标

### 2.1 目标（第一阶段）

第一批用户是几个人。【已定】他们注册并给出简历或意向后，**最先用上的是"寻找求职机会"**。【已定】第一阶段的完整闭环：

> 受邀注册 → 同意数据条款 → 上传简历或写意向 → 智能体生成档案草稿 → 本人确认档案 → 智能体按档案从多种来源找机会 → 本人看到一份带证据的个人机会清单

### 2.2 非目标（第一阶段不做，后续阶段再做）

- 针对岗位起草简历、求职信、申请文书、面试准备
- 任何对外发送：投递、发邮件、提交表单
- 申请阶段账本、截止提醒与通知
- 开放的自由注册

### 2.3 反目标（即使功能能跑，出现这些也算失败）

- 任何用户能读到其他用户的档案、简历、机会评估、来源或浏览器节点结果。
- 私人数据出现在公开实例、公开 API、站点地图、静态构建产物、共享缓存、日志、CI 产物或 Git 历史中。
- 智能体在没有本人确认的情况下对外发出任何东西，或在招聘网站账号里做出任何写操作。
- 绕过登录、破解验证码、规避风控；在条款明确禁止的平台上做自动抓取。
- 资格判断编造候选人事实（没有依据却判"满足"），或给未公布截止日期的机会编造日期。
- 改造过程中把现有公开实例 openagent.hk 弄坏或让其数据错乱。
- API key、账号密码、cookie 进入仓库、前端、日志或聊天记录。

## 3. 约束

- **平台**：继续使用 Cloudflare（Workers + D1），新增 R2（私有附件）与 Queues（按用户扇出任务）。【设计者判断：沿用现有技术栈】
- **大模型**：DeepSeek API。【已定】key 由管理员通过 `wrangler secret put DEEPSEEK_API_KEY` 注入 Workers Secrets，开发与测试使用假 key 或桩。代码中设可替换的模型接口层，DeepSeek 为默认实现。【设计者判断】
- **数据边界变化须知情同意**：简历与意向会发送给 DeepSeek 处理，简历文件会存入平台的 Cloudflare 账号。注册时必须有明确的知情同意步骤，写明发往何处、用于何事；不同意则不能使用智能体功能。不得宣称"端到端加密"或"仅本机持有"。（源自 #137 的授权要求）
- **公开与私有隔离**：公开实例的部署不绑定任何私有数据库或存储。（源自 #137）
- **采集合规底线**：只读；遵守 robots 与平台条款；不绕登录（浏览器节点由本人登录本人账号除外，见 §6.4）；不破解验证码；遇风控即停；每条数据留存来源、时间、原文证据。
- **测试与开发数据**：一律使用虚构数据；开发、预览、CI 环境不绑定生产私有数据。

## 4. 现状（2026-11-12 代码调研结论）

可复用：

- **公开情报管线**：来源 → 快照 → 候选 → 字段证据 → 变更集 → 审核队列（`lib/source-monitor.ts`、`lib/p1/*`），学术 / 政策 / 会议 / 机构发现几个采集器，真实性核验（`lib/authenticity/*`）。这些是领域无关的。
- **规则模块（纯函数）**：匹配打分（`lib/local-apply/matcher.ts`，其 `LocalProfile` 已参数化）、防招聘页内嵌指令的检查（posting-guard）、文书模板、docx 渲染。
- **审批门设计**（PRD-175，`lib/local-apply/approval/*`）：未登记动作一律拒绝、幂等键、批准与执行时载荷逐字节一致、批准有效期、只追加审计。第三阶段使用。

缺口：

- 没有任何用户、会话、角色、鉴权；D1 的 33 张表都没有 `user_id`；线上 API 全部只读。
- 公开表 `opportunities` 混有按人判断的列：`fit`、`why`、`action`、`masters_eligible`、`eligibility_details`、`phd_bridge_details`，另有若干"对我的价值"列。
- 领域词写死在代码里（论文关键词、"2027"、地区配置、"2027 校招"标签 SQL 等）；迁移文件把建表与种子数据混在一起。
- 没有简历解析，没有云端大模型调用，没有搜索能力，没有任何真实的对外执行器。
- Python 模块与多数 `.mjs` 模块（任务队列、工作台智能体、审批收件箱、成长路径等）是内存原型，未接线、不在 CI 中，只作领域模型参考，**不视为已有功能**。

## 5. 总体架构

```
                ┌─────────────────────────────── 公开仓库（同一份代码） ───────────────────────────────┐
                │                                                                                      │
  部署 A：公开实例（openagent.hk）                       部署 B：私有平台（独立 Worker，独立域名）
  ├─ 绑定：公开 D1（读写，由 cron 采集）                 ├─ 绑定：公开 D1（只读）
  ├─ 无私有 D1、无 R2、无 DeepSeek key                   ├─ 绑定：私有 D1（读写，按 user_id 隔离）
  └─ 现有页面与 cron 不变                                ├─ 绑定：私有 R2（简历文件，禁止公共访问）
                                                         ├─ 绑定：Queues（按用户扇出智能体任务）
                                                         ├─ Secrets：DEEPSEEK_API_KEY、搜索 API key、会话密钥
                                                         └─ 浏览器节点 API（节点主动拉取任务）
                                                                       ▲
                                                                       │ HTTPS，节点令牌
                                                         用户自己电脑上的浏览器节点（本人账号登录）
```

【设计者判断】私有平台以只读方式绑定公开 D1，直接复用公开实例已采集、已审核的机会；公开实例绝不反向读取私有库。D1 没有原生只读绑定，因此"只读"靠代码保证：公开 D1 只能经一个仅暴露查询函数的模块访问，私有平台代码中出现对公开 D1 的写语句即测试失败。

【设计者判断】私有平台是**同一仓库中的独立入口**：单独的 Worker 入口、路由与构建配置，复用 `lib/` 中的通用模块；不包含公开实例的页面、站点地图和两条写公开库的 cron。私有平台的用户需要看脑科学雷达时直接访问公开站点。

【设计者判断】私有平台**永不写公开 D1**。所谓"共享来源池"建在私有 D1 中（不带 `user_id` 的平台级表），公开 D1 只是 L1 的一个只读子集；公开实例的数据和页面不受私有平台任何操作影响。

## 6. 各部分设计

### 6.1 账号、登录与权限

- **注册方式**：邀请码注册 + 管理员审批，不开放自由注册。【设计者判断，基于"第一批只有几个人"】
- **登录**：邮箱 + 密码（WebCrypto PBKDF2 哈希），会话存私有 D1，浏览器侧为 `HttpOnly; Secure; SameSite=Lax` cookie。不用 Cloudflare Access 做用户登录，因为它不适合自助注册。【设计者判断；具体参数留给实施】
- **第一阶段不接邮件服务**：邀请码由管理员在后台生成后线下发给用户；忘记密码由管理员在后台生成一次性重置链接线下转交；不做邮箱验证。用户规模扩大后再接系统邮件。【设计者判断】
- **角色**：`admin` / `user`。管理员可审批、停用、删除账号，审核来源升级；**管理员界面不提供浏览用户私人内容的功能**。【设计者判断】
- **管理后台额外防护**：`/admin` 路径再套一层 Cloudflare Access。【设计者判断】
- **入口防绕过**：私有平台关闭 `workers.dev` 子域与预览 URL，或对其同样强制鉴权；所有页面、API、附件下载都在 Worker 内校验会话，不依赖前端隐藏或可伪造的请求头。（源自 #137）

### 6.2 按用户隔离数据

- 私有 D1 中每张用户数据表都有 `user_id NOT NULL`。
- D1 没有行级权限，因此**所有私有数据访问必须经过一个强制携带用户上下文的数据访问层**；禁止在路由中直接拼写私有表 SQL。用静态检查或测试守住这条规则。【设计者判断；实现方式留给实施】
- 私有响应一律 `Cache-Control: private, no-store`；私有页面不进站点地图、不被搜索引擎索引。
- 日志只记录 ID、计数、状态，不记录简历内容、档案内容或模型提示词与输出原文。
- R2 对象键以 `user_id` 为前缀；只能经已鉴权、已校验归属的 Worker 路由读取，不开放公共访问或长期签名链接。

### 6.3 档案（Profile）

- **输入**：上传简历（PDF / Word / 图片中的至少 PDF 与 Word【留给实施确定支持范围】）或一段自由文字意向，二者可兼有。
- **生成**：智能体调用 DeepSeek，把输入解析为结构化档案草稿。档案结构以现有 `JobDocProfile`（basics / education / experience / skills / outputs / target）为基础扩展，`target` 部分描述求职或升学目标：方向、岗位或项目类型（校招、社招、实习、博士、硕士、科研助理等）、城市 / 地区、届别或入学时间、资助或薪资期望、公司或机构偏好。
- **确认**：草稿必须由本人确认后才生效；本人可逐项修改。之后的智能体改动仍以草稿形式出现，本人确认后生效，保留上一版可回滚。（参考 PRD-281 的草稿 / 确认 / 回滚流程，但需要持久化实现）
- 档案中不能确定的事实标为"未知"，不由模型补全。
- 每个用户可有多个目标（例如"国内校招"和"港硕申请"并行）。档案（个人事实）挂在用户上；来源池、机会评估、找机会运行挂在**目标**上；额度挂在用户上。【设计者判断】

### 6.4 来源层（多来源找机会）

"各种来源都需要"。【已定】来源按可信度分层，每条来源与机会都带层级标签：

| 层级 | 内容 | 如何进入 | 可信度 |
|---|---|---|---|
| L1 官方来源 | 公开实例已有的 116 个来源（只读），以及私有 D1 中"平台共享来源池"里经管理员审核的官方招聘页 / 院校页 | 公开 D1（只读）+ 私有 D1 共享池 | 最高，可作最终依据 |
| L2 智能体发现的官方入口 | 智能体按用户目标调用搜索 API，定位公司 / 机构官方招聘入口 | 先进入该用户的私人来源池 | 高（需确认确为官方域名） |
| L3 用户 / 管理员提供 | 粘贴的链接、公司名单、招聘公告或公众号文章网址 | 该用户私人来源池 | 视具体来源 |
| L4 聚合平台公开页 | 牛客、实习僧、BOSS 直聘、智联、LinkedIn 等的公开可访问页面、开放接口或 RSS | 该用户私人来源池 | 中；标"来自聚合平台，待官方确认"，智能体尽量回溯官方链接 |
| L5 需要登录的页面 | 经用户本人浏览器节点读取（见 §6.5） | 仅该用户私人空间 | 中；结果只属于该用户 |

规则：

- **搜索 API**：需要一个对中文支持好的搜索服务（DeepSeek 本身不联网），key 放 Secrets。【留给实施：比较后选定一家】
- **私人来源转共享来源**：智能体为某用户发现的来源先进入其私人池并立即可用。智能体可以**提名**某个官方来源进入平台共享池，但必须由该用户点"允许分享这个来源"后才进入管理员审核（因为来源 URL 本身能反映求职意向）。审核与升级时只带来源本身（URL、机构、类型），不带提名人身份。【设计者判断】
- **聚合平台默认只记链接**：第一阶段不开发通用聚合平台抓取器。聚合平台的公开页面只以链接形式出现（例如搜索结果命中），由智能体尝试回溯到官方链接；需要读详情的走 L5 浏览器节点。是否对某个平台开启公开页抓取，由管理员逐个裁定并在后台开关。【设计者判断】
- **L1 机会的要求原文**：公开管线不存"官方要求原文"。私有平台在需要评估某条 L1 机会时，抓取其官方页面并抽取要求原文，存入私有 D1 的**平台级机会详情缓存**（官方公开信息，不带 `user_id`，多人共用，按过期时间刷新）；按人的判定只存在各自评估中。不改公开管线与公开 schema。【设计者判断】
- **L1 的覆盖面**：现有 L1 基本是脑科学 / AI 方向，对其他方向用户价值有限；其他方向第一阶段主要依靠 L2、L3、L5，随共享池审核逐步积累。私有平台的机会类型与地区使用自己的可配置字典（含社招、硕士等），不沿用公开表的枚举。【设计者判断】
- **防提示注入**：任何抓取来的页面内容在交给大模型前先过 posting-guard，命中则不用于起草、匹配结果标注风险。
- **采集频率**：用户手动触发"找机会"随时可跑；另对每个用户的私人来源池每日刷新一次。【设计者判断；可配置】
- 去重：同一机会在多个来源出现时合并，并保留所有来源证据（可参考 `lib/wiki/*` 的模糊去重）。

### 6.5 浏览器节点（读取需要登录的页面）

【已定】需要登录才能看的页面，调用一台机器上的浏览器去看；登录的是**每个用户自己的招聘网站账号**。

- **默认部署位置：用户自己的电脑**。【设计者判断】用户在自己电脑上运行一个节点程序，用自己的浏览器登录自己的账号。账号与 cookie 不离开本人电脑；本人可看到智能体打开了哪些页面，遇到验证码可当场处理。
- **备选：管理员的机器代管**。用户不方便时，可在管理员机器上为其单独建一个浏览器配置，首次登录由本人远程或当面完成；不同用户配置严格隔离，管理员不进入他人配置。**此备选不在阶段 1c 范围内**，1c 只做"用户自己电脑"一种部署；节点协议保持一节点绑定一用户，以便日后支持代管。【设计者判断】
- **通信**：节点主动向私有平台拉取任务（不需要云端反连、不需要开放端口），以 HTTPS + 节点令牌认证。令牌绑定到单个用户，首次绑定需本人在网页上确认，可随时解绑或吊销。
- **任务路由**：某用户的 L5 任务只派给绑定该用户的节点；结果（页面正文快照、URL、抓取时间）只写入该用户私人空间。
- **云端从不保存**账号、密码、cookie 或浏览器会话。
- **行为边界**：只读——只打开页面与读取内容；不点投递、不发消息、不改账号设置。遇验证码或风控提示即停，任务标为"需要人工处理"。
- **节奏**：模拟正常人浏览频率，限制每小时 / 每日页面数，不做批量翻页抓取。【具体数值留给实施，需可按平台配置】
- **风险告知**：很多平台条款禁止自动化访问，即使用真人账号也可能被限流或封号；绑定节点时向用户明确提示此风险，每个平台可单独关闭。
- 实现技术（Playwright 持久化配置 / 现有浏览器扩展等）【留给实施】。

### 6.6 匹配与个人机会清单

- 对每个候选机会，结合用户档案与目标，产出**按用户隔离的评估**，替代现在公开表里的 `fit` / `why` / `action` / `masters_eligible` 等列在私有平台中的作用。
- 评估内容：
  - 官方要求逐条列出原文与来源证据；每条判定 `满足 / 不满足 / 未知`。没有候选人事实支撑时只能判"未知"。
  - 截止状态：明确日期 / 滚动申请 / 未披露（未披露不得编造日期）。机会开放状态与本人申请状态分开存储。
  - 匹配理由与主要差距，引用档案中的具体事实。
  - 来源层级与真实性状态（复用 `lib/authenticity/display.ts` 口径）。
- 打分：以现有规则匹配器为基线，DeepSeek 负责理解要求原文与重排；【设计者判断】最终排序规则【留给实施】。
- 用户对每条机会可标记：感兴趣 / 不感兴趣 / 已处理，作为后续推荐的反馈。

### 6.7 智能体执行与成本

- 用户触发"找机会"或每日刷新时，私有 Worker 把任务按用户放入 Queues，由消费者逐步执行：拆解目标 → 选来源（L1 查询 + L2 搜索 + L3/L4 抓取 + L5 派发节点）→ 抽取与去重 → 评估 → 写入个人清单。
- 每个用户设大模型调用与搜索调用的日额度上限，超出即暂停并提示。【设计者判断；数值留给实施】
- 每次运行记录：耗时、模型调用次数与 token、搜索次数、产出机会数、失败原因，供管理员查看（不含私人内容原文）。

### 6.8 数据权利与运维

- 用户可导出自己的全部数据（档案、目标、机会清单、来源池、评估）。
- 用户可删除账号：删除私有 D1 中该用户全部行与 R2 中全部对象，吊销所有会话与节点令牌。需在文档中如实说明：D1 时间回溯备份在保留期内仍含已删除数据，保留期结束后才彻底消失。
- 管理员可停用账号（立即失效所有会话与节点令牌）。
- 更新 README 与 `docs/OPERATIONS.md` 中"个人材料仅本地"的说明，准确描述新模式的数据流（D1 / R2 / DeepSeek / 搜索服务 / 浏览器节点）与授权边界；原本地 CLI 仍可作为"仅本地"模式保留。【设计者判断】

## 7. 对公开仓库与公开实例的改动范围

【设计者判断】第一阶段只做私有平台需要的解耦，不全面重构公开实例：

- 必做：私有平台不读取、不使用公开表中的 `fit` / `why` / `action` / `masters_eligible` / `eligibility_details` / `phd_bridge_details` 等按人判断列；这些列在公开实例中视为该实例自己的编辑内容，暂不迁移。
- 必做：新增的私有平台代码（鉴权、私有 schema、智能体、来源层、节点 API）不得写入任何领域专属词（脑科学、2027 等），领域由用户目标驱动。
- 必做：私有平台的 schema 迁移与公开 D1 迁移分开存放、分开执行。
- 后续：把公开实例中写死的论文关键词、地区配置、"2027 校招"标签、品牌文案改为实例配置；拆分迁移中的建表与种子数据。

## 8. 分阶段交付

【设计者判断】

- **阶段 1a：账号与隔离地基**——私有部署骨架、邀请注册与审批、登录会话、知情同意、按用户隔离的数据访问层、入口防绕过、导出 / 删除。
- **阶段 1b：档案与找机会**——简历上传与解析、意向描述、档案草稿与确认、L1–L4 来源、搜索 API、Queues 执行、评估与个人机会清单。
- **阶段 1c：浏览器节点**——节点程序、绑定与令牌、L5 任务派发与回传、风控停止与人工处理。
- **阶段 2**：材料准备（复用 drafter / docx）、审批门云端化（PRD-175 语义 + 按用户隔离）、申请阶段账本、截止提醒。
- **阶段 3**：真实对外执行器（邮件、表单），每次执行都需本人确认。

- [ ] 公开实例部署配置中不存在私有 D1、R2、DeepSeek key 绑定；公开实例的页面、API、cron 行为与改造前一致（回归测试通过）。

## 10. 风险

- **平台封号**：浏览器节点访问招聘平台可能违反条款，导致用户账号被限流或封禁。缓解：低频、只读、按平台开关、明确告知。
- **数据出境与第三方处理**：简历发往 DeepSeek，须在同意条款中写明；如有用户不接受，可后续提供替代模型实现。
- **隔离漏洞**：D1 无行级权限，隔离依赖数据访问层纪律；缓解：强制数据访问层 + 跨用户测试 + 静态检查。
- **模型误读**：档案或资格判断出错。缓解：档案本人确认、资格无依据判"未知"、保留原文证据。
- **成本**：搜索与大模型按量计费。缓解：每用户日额度与运行记录。
- **现有采集失败率**（issue #13）会影响 L1 来源质量，与本项目独立推进。
