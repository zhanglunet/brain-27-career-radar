# P2 学术情报雷达 PRD

- 版本：v0.12.0
- 日期：2026-08-01
- 状态：P2.1—P2.5 已上线，P2.6 审核工作台待开发
- 网页版：`/prd/academic`

## 1. 背景

机会雷达已经能跟踪博士、科研助理和校招入口，但前沿学术机会常先出现在导师主页、实验室项目和新论文中。系统需要从“岗位清单”扩展为“人—论文—项目—议题—政策”的学术情报层。

## 2. 目标与非目标

### 目标

1. 建立可解释的重点导师跟踪池，首批覆盖英国、中国内地、中国香港和全球代表团队。
2. 自动发现导师近 18 个月论文，保存 DOI、作者关系、版本、主题、来源和核验状态。
3. 导师官方主页沿用现有 Cron、快照、失败隔离和日志能力。
4. 论文候选必须透明标注置信度，身份不确定时不得伪装成已核验成果。
5. 页面同时适配桌面和手机。

### 非目标

- 不制作缺乏透明口径的“全球导师排名”。
- 不批量收集私人邮箱或绕过登录、验证码、付费墙。
- 不以引用量替代当前招生意愿或与用户背景的匹配程度。
- P2.1/P2.2 不自动向导师发送邮件，不自动提交申请。

## 3. 用户故事

1. 我希望按地区、机构、主题和研究方法寻找重点导师。
2. 我希望看到导师官方主页最近何时被系统成功检查。
3. 我希望看到近期论文，并区分“自动候选”和“人工/规则已核验”。
4. 我希望从论文迅速判断其与计算神经科学、BCI、认知科学和 NeuroAI 的关系。
5. 维护者希望每次学术同步均有运行摘要和逐实体事件日志。

## 4. 本期范围

### P2.1 导师雷达

- `researchers`：身份、机构、地区、角色、研究主题、方法、申请价值、招募观察状态、优先级。
- `researcher_identities`：ORCID、Crossref、Europe PMC 等外部身份；区分已核验和待核验。
- `researcher_sources`：导师与官方主页、实验室、CV、论文页的来源关系。
- `/researchers` 与 `/api/researchers`：搜索、地区和优先级筛选。
- 首批 16 位导师；牛津、剑桥、UCL、中国内地和中国香港为核心优先级。

### P2.2 最新论文

- `papers` 与 `paper_authors`：DOI/PMID/PMCID/arXiv 去重键、作者关系、出版日期、版本状态、主题、摘要、来源和核验状态。
- Cron 调用已启用论文数据库；当前为 Crossref、Europe PMC、arXiv、PubMed、PMC、DOAJ，按每位导师近 18 个月、每库最多 5 条结果进行有限发现。
- 作者规范化匹配 + 神经/脑/认知/学习/BCI 等标题关键词匹配；低于阈值不写入。
- 新发现默认 `candidate`、`published=false`，页面可作为透明候选展示，但不得标为已核验。
- `/papers` 与 `/api/papers`：关键词、核验状态筛选及最新同步摘要。

### P2.2.1 论文数据库目录

- `paper_providers` 保存数据库能力、覆盖、认证方式、配置项、启用状态和最近同步健康。
- `paper_provider_sync_logs` 保存每次 Cron 中每个数据库的检查数、候选、新增和失败。
- `paper_provider_records` 保存论文在不同数据库中的记录关系；同一 DOI/PMID/PMCID/arXiv ID 合并为一篇论文，但来源不丢失。
- `/paper-sources` 与 `/api/paper-providers` 公开显示已启用、可接入、需配置和规划中的全部数据库。
- 自动发现：Crossref、Europe PMC、arXiv、PubMed、PMC、DOAJ。
- arXiv 不提供机构字段，高同名风险导师安全跳过；PubMed/PMC 使用 NCBI 无密钥限速；PMC 只声明可用开放全文，不承诺全库全文。
- 需要配置：OpenAlex、Semantic Scholar、ORCID、Unpaywall、CORE。
- 研究中：OALib、东壁；未确认稳定公开 API 与机器访问许可前不自动抓取。

## 5. P2.3—P2.5 已交付范围

- P2.3 研究项目：`research_projects` 保存计划、牵头机构、经费、状态、研究方向与机会价值；项目进入 `/policies`、全局搜索和知识图谱。
- P2.4 议题雷达：`research_topics` 保存议题动量、政策/项目/论文证据计数；首批覆盖 NeuroAI、神经技术、AI for Science、心理健康、青年人才和国际合作。
- P2.5 科研政策：`policy_feeds`、`research_policies`、`policy_versions`、`policy_candidates`、`policy_sync_runs` 构成独立管线；首批覆盖 UKRI、Horizon Europe、EIC、国家自然科学基金和香港 RGC。
- `/policies` 与 `/api/policies` 提供地区、类型、状态和关键词筛选；政策截止日期进入 `/calendar`，日报/周报/月报增加政策和项目统计。
- 自动发现的新政策链接只进入候选区；公开页面只返回 `published=1` 且 `review_status=verified` 的条目。Cron 可保存官方页面内容哈希和版本证据，但不自动改写人工核验摘要。

## 6. 后续范围
- P2.6 审核工作台：候选合并、身份确认、论文/政策版本关系与通知摘要。

## 7. 业务规则

- 导师“优先级”表示用户匹配和监控频率，不表示学术排名。
- 论文去重顺序为 DOI > PMID > PMCID > arXiv ID > 规范化题目、作者和年份。
- 预印本与正式论文保留版本关系；撤稿、更正不得覆盖为普通论文。
- 官方主页失败不会删除导师；外部 API 失败不会清空既有论文。
- 未核验外部身份只能产生候选，不能自动升级为已核验。
- 所有时间使用 UTC 保存，界面按用户环境显示。

## 8. 自动运行与日志

Cron 为 `0 1,7,13,19 * * *`。每次触发并行执行：

1. 现有来源健康检查、快照、字段抽取和审核路由。
2. 导师论文发现；写入 `academic_sync_runs` 和 `academic_events`。
3. 政策目录发现与已核验政策版本巡检；写入 `policy_sync_runs`、`policy_candidates` 和 `policy_versions`。

请求限制为 15 秒，单次最多 16 位导师、每位每库最多 5 篇论文。NCBI 请求在无密钥模式下主动限速；日志不得保存密钥、完整网页正文或私人联系方式。

## 9. 验收标准

- D1 迁移可从空库顺序执行，种子包含 16 位导师及对应官方来源。
- `/researchers`、`/papers`、两个 API 和 `/prd/academic` 可正常访问。
- 论文发现具有超时、数量上限、作者和主题筛选、DOI 幂等写入。
- 学术同步成功、部分失败和全部失败均写入运行摘要。
- 候选不会被 API 标为“已核验”。
- 375px 手机宽度和桌面宽度均可阅读、筛选和打开来源。
- `npm run verify` 全部通过。
- `/policies`、`/api/policies`、政策全局搜索、日历截止和知识图谱关系均可从 D1 正常读取。
- 新发现候选不能自动成为公开政策；单一政策源失败不影响职业、论文和机构发现管线。

## 10. 发布与回滚

- 生产迁移前导出 D1 备份；迁移只新增表和来源种子。
- 应用回滚不删除新表；必要时可停用 Cron 或关闭导师来源。
- Crossref 不可用时，导师主页巡检和职业机会流程仍可独立运行。
